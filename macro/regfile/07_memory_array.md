# 命令メモリ — TLAT アレイ / REG4x16（実装済み）

16 word × 8 bit = 128 bit の命令メモリを、`REG4x16`（4bit × 16word）×2 で作る。
**2026-09-10 時点で REG4x16 はレイアウト完了・DRC クリーン**（トップのピンのみ未定義）。

再現: `python3 scripts/block_report.py lef/TR-1um_STDCELL.gds REG4x16 --bits 64`

---

## 1. なぜアレイ化したか

`td4_mem` をブラックボックス化して合成し、実測で切り分けた結果:

| | 面積 |
|---|---:|
| `td4_soc_arr` 全体（メモリも FF） | 1.429 mm² |
| うち メモリ以外（コア + 書込制御、FF 25 / 組合せ 83） | **0.277 mm²** |
| **うち 命令メモリ 128bit** | **1.152 mm²（全体の 81%）** |

→ メモリだけをカスタムアレイに置き換える。**コア側は一切触らない。**

## 2. TLAT — 12T ratioless ラッチ ビットセル

`lef/TR-1um_STDCELL.gds` に実装済み。**37.8 × 59.4 µm / 12 Tr（PMOS W=7.2 / NMOS W=3.4 / L=1.0）**

GDS から抽出した回路（`spice/TLAT_extracted.spi`、`scripts/gds_extract.py` で再生成可）:

```
D ──[TG-W: WR]──> n3 ──INV1──> n1 ──INV2──> n2 ──[TG-F: WRB]──> n3   (保持ループ)
                                │
                                └──INV3──> n4 ──[TG-R: RD]──> Q
```

| 特徴 | |
|---|---|
| **TG-F が書込中に帰還を切る** | ライトドライバが帰還 INV と戦わない = **比設計不要（ratioless）** |
| **読み出しが INV3 の専用バッファ経由** | 保持ノードに触らない = **リードディスターブが原理的にゼロ** |
| Q = D（非反転） | |
| セル内に基板/N-well タップを内蔵 | アレイ内に TAP 列は不要（境界の TAP2S のみ） |

ワードライン `WR/WRB/RD/RDB` は M1 で左右端に出ており、**横 abut で繋がる**。
ただしセル内では M1 が 9.2 µm 途切れ、**TG のゲート poly を渡る**構造なので、
ワードラインは M1–poly の梯子になる（1タイル 4bit なら影響は無視できる）。

ビット線 `D`/`Q` は M2 パッド（x ≈ 2.7 / 35.1）のみでセル上下端に届かないので、
**縦の M2 は TLAT64 の中で通しで引く**。ミラーは Y 方向のみなので x は動かず一直線で拾える。

## 3. REG4x16 — 実装された階層

```
TLAT      37.8 × 59.4    12Tr  ビットセル
TAP2S     10.8 × 59.4     0Tr  タップ（列端）
TLAT4     TLAT ×4 + TAP2S            162.0 × 59.4
TLAT8     TLAT4 ×2（Y ミラー @114.0）  162.0 × 114.0   ← 4.8 µm 重ねて vdd レール共有
TLAT64    TLAT8 ×8 @109.2            162.0 × 878.4   ← 実効行ピッチ 54.6

DEC0      59.4 × 86.4    16Tr  1行分のデコーダ（P W=12.2 / N W=4.6）
          NAND4→SELB(8T) / INV→RD(2T) / NOR2→WR=SELB nor WEB(4T) / INV→WRB(2T)
DEC2      DEC0 ×2（X ミラー @114.0）
DEC16     DEC2 ×8 @109.2  → 878.4 × 86.4 を **90° 回転**してアレイ左に貼る

REGBUF    37.8 × 59.4     8Tr  1bit のデータバッファ（DD→D 書込 / QQ→Q 読出、各2段）
REGBUF4   REGBUF ×4 + TAP2S
ADDBUF    99.0 × 63.4    20Tr  ADDRB=INV(a) / ADDR=INV(ADDRB) ×4 + WEB 用 ×1

REG4x16   TLAT64 + DEC16 + REGBUF4 + ADDBUF
```

### 実測（`scripts/block_report.py`）

| | |
|---|---|
| フットプリント | **248.4 × 933.0 µm = 0.232 mm²** |
| トランジスタ | **1,076 Tr = 16.8 Tr/bit** |
| bit 単価 | **3,621 µm²/bit**（デコーダ・バッファ・タップ込み） |
| ビット列 x | セル / バッファとも 0, 37.8, 75.6, 113.4 — **一致** |
| 行ピッチ | アレイ / デコーダとも 54.6 µm、**16行すべて中心ずれ 0.00** |

### 設計上の決定と根拠

1. **アドレスは R/W 共通・デコーダ1個** — TD4 はリードとライトが同時に起きず、
   Load 時は同じアドレス。`raddr = exec ? pc : ld_addr` の 2:1 MUX はコア側にある。
2. **デコーダはアクティブロー（NAND4）** — `RDB = SELB` が直結で取れるので1段減る。
   `WR = SELB nor WEB` で WE ゲートも NOR2 一段。
3. **ADDRB はブロック内で生成** — 1本あたりの負荷は NAND4 8個 ≈ 193 fF +
   M2 878 µm ≈ 132 fF = **約 325 fF**。`INV_X1` で約 1.2 ns。外部から2ブロックに
   配ると倍になり、このライブラリには X1 しか無いので不利。
   `ADDRB=INV(a)` / `ADDR=INV(ADDRB)` の**平衡型**にしてスキューを INV 1段に固定。
4. **8bit 一括ライト** — 下位ニブルをコア側のステージングレジスタに溜めるので、
   書込ワードラインが行あたり1本で済む（合成後の組合せセルが 536 → 289 に減った）。
5. **メモリにリセットを持たせない** — セルごとのクリア Tr が省ける。副次的に
   リセットしてもプログラムが消えない。

### 守るべきタイミング

`ADDRB` は `ADDR` より INV 1段（約 1.2 ns）遅れるため、アドレス遷移中に
**2行が同時選択される瞬間**がある。

- リード側は無害（コアはクロックエッジでサンプルする）
- **ライト側は致命的** → `WEB` は**アドレス確定後**に落とすこと。
  `WR = SELB nor WEB` のゲートがそのまま保護になる。

## 4. 面積

| | 面積 | 配置後 |
|---|---:|---:|
| 周辺ロジック（コア + 書込制御、標準セル） | 0.277 mm² | @util60% → 0.462 mm² |
| 命令メモリ 128bit を **FF で実装** | 1.152 mm² | 合計 2.382 mm²（コアの 70%） |
| 命令メモリ 128bit = **REG4x16 ×2** | **0.464 mm²** | 合計 **0.926 mm²（コアの 27%）** |

有効コア 1,840 × 1,840 µm = 3.386 mm²。**2.5倍圧縮**。

8bit ワードにするときは **X ミラーしてデコーダを中央に置く**構成を推奨:

```
[ ARRAY4 | DEC ][ DEC | ARRAY4 ]     bit0-3 / bit4-7
```

2つのアレイがデコーダ帯で隔てられるので**ワードラインが物理的に分離**し、
2つのデコーダが同じ網を駆動する競合が起きない。アドレスバスも中央1箇所で済む。

## 5. 残っている作業

| | |
|---|---|
| **REG4x16 のトップピン** | まだラベル無し。`ADDR[3:0]` / `WEB` / `DD[3:0]` / `Q[3:0]` / `vdd` / `vss` を (49,1) にピン矩形付きで |
| `TLAT` の `WR/WRB/RD/RDB` | ラベルが (48,1)。外部ピンなら他セル同様 (49,1) へ |
| `DEC0` / `ADDBUF` の信号ラベル | (49,1) の形状はあるがテキストが無い |
| **LVS** | DRC はクリーン。次は回路図/ネットリストとの照合 |
| **SPICE** | 下記 |

### SPICE で見るべき順序

1. **リードパス（最優先・クリティカルパス）** — 選択セルの INV3 が TG-R 経由で
   「M2 878 µm + 非選択15セルの TG ドレイン容量」を駆動し、REGBUF の2段 INV が受ける。
   ワースト（非選択15セルが全部逆データ）で測る。
   これが `PC → 命令 → セレクタ → 加算器 → FF` に乗る。
2. **書込マージン** — TG-W の駆動力 vs 保持ノード容量。ratioless なので余裕はあるはず。
3. **D のホールド時間** — `WRB = INV(WR)` のスキューで、WR 立ち下がりに TG-F が
   TG-W より先に導通し始める。D が同時に変わると一瞬競合する。
4. **ADDR 変化 → WEB 立ち上がりの最小間隔**（上記タイミング規則の確定）
5. **保持リーク** — 完全スタティックなので通常は問題にならないが確認。

## 6. C4004 への流用

C4004 の Scratchpad は **16 word × 4 bit** — **`REG4x16` そのもの**。
PC/スタック 4 word × 12 bit は横3個（深さは 16 のうち 4 語だけ使う、
または 4 word 版を派生させる）。**セル・デコーダ・バッファの設計はそのまま使える。**

TD4 で実シリコン実証できれば、C4004 の最大の面積課題（アレイ化で −0.90 mm²）が解決する。
