# STDCELL ライブラリ 2 世代の差分調査

調査日: 2026-09-14 / 対象: `TR-1um_SCLK_SPI/lef/TR-1um_STDCELL.{lef,gds}`（行高 64.8）と
`TR-1um_I2C_2026/lef/TR-1um_cells.lef` + `TR-1um_STDCELL.gds`（行高 59.4、TD4 と同一）

## 1. 結論

**59.4 版が厳密に上位互換**。64.8 版にしか無い実体セルは 1 つも無い。

| | 64.8 版 (SCLK_SPI) | 59.4 版 (TD4 / APR_2026) |
|---|---|---|
| LEF MACRO 数 | 31 | 48（論理 39 + メモリ階層 9） |
| GDS セル数 | **29** | **51**（+ `via_1` PCell 2 個） |
| 行高 | 64.8 µm | **59.4 µm（−8.3%）** |
| 論理セルの幅 | — | **全セル 64.8 版と同一** |
| 電源ピン名 | `VDD` / `GND` | **`vdd` / `vss`（小文字）** |
| FF の内部観測ピン | 無し | **`CKB` / `CKP` / `QM` / `QS` を追加** |
| Liberty | `TR1um_5_stdcell.lib`（プレースホルダ） | **`tr1um_typ_5v0_25c.lib`（実特性化・193KB）** |

## 2. セル単位の差分

### 2-1. 共通セル 29 種 — 幅は完全一致、高さだけ 64.8 → 59.4

`INV_X1` 10.8 / `NAND2` `NOR2` `BUF_X1` `BUF_X2` 16.2 / `AND2_X1` `NAND3` `NOR3` `OR2` `RSLATCH`※ 21.6 /
`NAND4` `NOR4` `AND3_X1` `OR3` `XOR2` `XNOR2` 27.0 / `AND4_X1` `OR4` `MUX2` `BUFTH` `DEL1` 32.4 /
`DFF` `DFFRB` `DFFS` 64.8 / `MUXDFFRB` 97.2 / `TAP2` `FILL2` 10.8 / `TAP3` `FILL3` 16.2
（※ `RSLATCH` は 27.0）

**幅が 1 つも変わっていない** ＝ サイトグリッド 5.4 µm とセル幅のラインナップは両世代で同じ。
したがって **配置器・ルータの x 方向の前提（TAP ピッチ 534.6、FILL2/FILL3 の刻み、5.4 µm 隙間禁止）は
そのまま通用する**。変わるのは `ROW_HEIGHT_UM` と、そこから導かれるコア高だけ。

### 2-2. 64.8 版にしか無い MACRO = 2 個、どちらも **実体が無い**

```
BUF_X4, BUF_X16   ← LEF に MACRO はあるが GDS にセルが無い
                     ★ **実装しないと決めた**（U3、2026-09-16）。正本の v59_4 は
                       GDS・LEF・Liberty・cell_char のどこにも持っていないので既に清潔。
                       幽霊 MACRO が残るのは**凍結した v64_8 の LEF だけ**で、
                       凍結世代は触らない（決定 17）。踏んでも
                       `gen_placement_gds.py` が `cells missing from …` で止まる。
                       駆動力が要るなら `BUF_X2` を並べる。
```

これは `TR-1um_SCLK_SPI/design_notes.md` §14.6 で「使うと黙って `BUF_X1` になる」と
指摘されたまま**未解決**だった項目。59.4 版はこの 2 つを LEF から外し、代わりに
**実体のある `INV_X2` を追加**している。つまり **59.4 版で既に直っている**。

### 2-3. 59.4 版で追加された 19 MACRO

| 分類 | セル |
|---|---|
| ドライブ系 | **`INV_X2`**（実体あり） |
| 物理セル | **`FILL1`**（5.4 µm。優先コリドーを増やしたとき step3 が落ちるのを防ぐ）、**`TAP2S`** |
| メモリビットセル | `TLAT`（12T ratioless ラッチ 37.8×59.4） |
| メモリ階層 | `TLAT4` `TLAT4B` `TLAT8` `TLAT8B` `TLAT64` `TLAT128` |
| デコーダ | `DEC0` `DEC2` `DEC16` |
| バッファ | `REGBUF` `REGBUF4` `REGBUF8` `ADDBUF` |
| マクロ | **`REG4x16`**（248.4×933.0 / 1,076 Tr）、**`REG8x16`**（399.6×933.0 / 1,876 Tr） |
| 横置きの実験 | `MEMPORT`（`TR-1um_PNR.{gds,lef}` 側。`REG8x16` を R90 して水平パッド列に変換）。**採用せず。U89 でフローの入力から外した** |

## 3. 移行で必要になる作業（SCLK_SPI を 59.4 版で作り直す場合）

| 作業 | 影響 | 難度 |
|---|---|---|
| `ROW_HEIGHT_UM` 64.8 → 59.4 | コア高が約 8% 縮む。チャネル予算 `ROUTE_CH_HEIGHTS` は再測定 | 低（config 1 行） |
| 電源ピン名 `VDD`/`GND` → `vdd`/`vss` | LVS ネットリスト生成・電源ピン付け・`verify_*` の文字列比較 | **中（全スクリプト横断）** |
| `BUF_X2` 依存の見直し | 59.4 版の `BUF_X2` は実体あり。加えて `INV_X2` が使える | 低 |
| `TR1um_5_stdcell.lib` → `tr1um_typ_5v0_25c.lib` | 合成の面積・遅延が実特性値になる。セル選択が変わり得る（要再合成） | 中 |
| FF の `CKB`/`CKP`/`QM`/`QS` ピン | 未接続で問題ないが、LVS のポート数照合と `verify_port_connectivity` が拾う可能性 | 要確認 |
| `TR-1um_STDCELL.spice`（SCLK_SPI 独自） | 59.4 版は `lef/simulation/<cell>.spice` の個別ファイル方式 | 中 |

## 4. 決定（2026-09-14）

**`stdcell/v59_4/` を正本**とし、`stdcell/v64_8/` は `legacy/` 相当として凍結（SCLK_SPI の
既提出 GDS を再現する必要が出たときのためだけに残す）。

理由:
1. 64.8 版にしか無い実体セルがゼロ
2. 64.8 版の既知バグ（`BUF_X4`/`BUF_X16` の実体欠落、`BUF_X2` の LEF FOREIGN 不整合）が
   59.4 版では解消済み
3. Liberty が実特性化されている（14,179 本の ngspice デッキから生成、`verify_lib.py` で
   格子外照合 0.2〜1.0% を確認済み）
4. セル幅が同一なので、配置・配線の x 方向ロジックに変更が要らない
5. メモリマクロ・`INV_X2`・`FILL1` が使えるようになる

**ただし電源ピン名の大小文字（`VDD`/`GND` → `vdd`/`vss`）だけは全スクリプトを横断する変更**
なので、APRtools への集約時にまとめて `apr/rules.py` の定数 1 箇所に寄せること。
