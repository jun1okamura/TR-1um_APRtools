## 1. ダイとフレーム

| 項目 | 値 |
|---|---|
| ダイ | **2,500 × 2,500 µm**、bbox ±1250、dbu 0.001 |
| 使うセル | **`OSS_FRAME_GIO`**（`OSS_ESD_5V_DIO` × 14 + VDD + VSS） |
| パッド総数 | **16**（信号 14 + VDD + VSS）。**`P8` は存在しない**（VSS がその位置） |
| ESD セル外形 | 400 × 240 µm |
| パッド開口 | 80 × 80 µm（GIO 版） |
| コーナー `OSS_FRAME_CNR` | 360 × 360 µm |
| **フレーム開口** | **1,840 × 1,840 µm = 3.386 mm²**（四隅まで含めて正方形） |

**開口は `frame_opening()` が GDS を二分探索して実測する**。1840 角は全層で完全に空き、
1844 角で M1 / V1 / M2 / WN に当たる。層ごとの内壁:

```
M1, M2, WN, ピン  ±920.0
V1                ±921.0
AN                ±922.0
CO                ±923.2
GC                ±923.6
AP                ±928.4
```

> **★ `lef/TR-1um_frame.lef` の OBS を設計の根拠に使わないこと。**
> OBS は四隅を 360×360 の矩形（x 800…1160, y 800…1160）で粗く塞いでおり、
> そのまま読むと「幅 1,600 を超えると開口が 1,840 → 1,600 に落ちる」という**実在しない崖**が出る。
> `OSS_FRAME_CNR` の実図形は外側 2 辺に沿った L 字で、内側の角は空いている（実測: (780…860)² に何も無い）。
> TD4 の `CORE_WIDTH_UM = 1598.4` はこの崖を避けて決めた値。
> 比較用に `frame_opening_lef()` はあるが**設計には使わない**。

フレームは**四隅のうち 3 隅に自前の PTECT ボックス**を持つ（右下 (810,−1120)-(1120,−810) など）。
SCLK_SPI は GND バスバーを y=−838 に置いてここに丸ごと入れてしまい、y=−795 に上げて 15 µm の
クリアランスを取った。**対称性より、そこに実際に何があるかが優先。**

`FRAME_HARD_LAYERS`（コアが当たってはいけない層）:
`(3,1) (3,2) (8,1) (11,0) (13,0) (14,0) (19,0) (20,0) (48,1) (49,1) (140,0)` — **ウェル (140,0) も含む**。

## 2. パッド配置（GDS 実測、`pin_list.py` 生成）

**ボンドパッド中心は半径 1,040 µm、各辺 ±200 / ±600 µm。**
パッド番号は `P1` から**反時計回り**。`P8` = VSS、`P16` = VDD。

| 辺 | パッド（左→右 / 上→下） |
|---|---|
| **上** | `P2`(−600) `P1`(−200) **`VDD`**(+200) `P15`(+600) |
| **右** | `P14`(+600) `P13`(+200) `P12`(−200) `P11`(−600) |
| **下** | `P10`(+600) `P9`(+200) **`VSS`**(−200) `P7`(−600) |
| **左** | `P6`(−600) `P5`(−200) `P4`(+200) `P3`(+600) |

基板配線用（ダイを表から見て左上から**時計回り**）:
TOP `P2 / P1 / VDD / P15` → RIGHT `P14 / P13 / P12 / P11` →
BOTTOM `P10 / P9 / VSS / P7` → LEFT `P6 / P5 / P4 / P3`

> `TD4/reference/05_pin_io_plan.md` §7 の「LEF 実測で ±215.85 / ±584.15」は**採らない**。
> `pin_list.py` が `OSS_PAD` インスタンスを GDS から読んだ値が ±200 / ±600 で、
> パッドセル幅 400 µm と整合する（パッド 1 は x −400…0 を占め、その端子が −270/−220/−180）。

## 4. `OSS_ESD_5V_DIO` の使い方

| ピン | 向き | 意味 |
|---|---|---|
| `OUT` | in（コア→パッド） | 出すデータ |
| `HIZ` | in（コア→パッド） | **1 でドライバを放す（Hi-Z）／0 で駆動** |
| `PAD` | inout | ボンディングパッド。**上辺にコア側へのスタブも出ている** |

極性は I2C 版がトランジスタレベルで追って確定した（ピン名からの推測ではない）:

```
HIZ = 1  ->  出力ドライバ OFF（Hi-Z、入力専用）
HIZ = 0  ->  出力ドライバ ON（OUT で駆動）
```

### 実測特性

**出典は `stdcell/v59_4/tr1um_typ_5v0_25c.lib` の `cell (OSS_ESD_5V_DIO)`**（特性化フローが生成）。
`pad_cell : true` / `dont_use : true` / `dont_touch : true` が付いており、
**合成が勝手に挿さない**ようになっている。`function : "OUT"` / `three_state : "HIZ"`。

| 項目 | 値 |
|---|---|
| `HIZ=0` の伝達 | `PAD = OUT`（非反転） |
| OUT→PAD 遅延 | **約 0.17 ns / pF**（CL=10 pF で 10.6 ns、50 pF で 17.0 ns） |
| 3 ステート enable | 9.4 ns（CL=10 pF） |
| 3 ステート disable | 7.9 ns（負荷非依存） |
| 入力容量 | `OUT` **36.192 fF** / `HIZ` **86.827 fF**（`.lib` 実値） |
| **`PAD` 容量** | **4,844.8 fF = 4.84 pF**（パッド金属 + ESD 素子。`.lib` 実値） |
| セル面積 | 96,000 µm²（= 400 × 240） |
| 駆動能力（VDD/2） | PMOS **+15.8 mA** / NMOS **−13.8 mA**（LED 直結可） |
| 駆動段 Tr 幅 | W = 300 / 150 µm |

### 入力として使うとき

**入力バッファは入っていない**ので `PAD` の上辺スタブをコアの標準セル入力に直結できる。
ただし **`PAD` 容量 4.8 pF は外から見た負荷**で、外部ドライバが弱いと立上りが鈍り、
鈍った波形をコアに配ると各段で貫通電流が増える。

→ **入力は全部 `BUFTH` で受ける**（`insert_bufth.py` が P&R 前に挿入）。
`BUFTH` はシュミット（`.lib` の `input_voltage(BUFTH_in)`: **`vih = 3.709 V` / `vil = 1.201 V`、
ヒステリシス 2.508 V**）なので
`CLK` / `RSTN` のチャタリングや遅い縁を整形する。**外部整形も `IBUFS` 自作も不要。**
サイズ **32.4 × 59.4 µm（6 サイト）**、area 1,924.6、入力 `A` の容量 **63.444 fF**。

> `.lib` のコメント: 「シュミットトリガ。…ライブラリ共通の `input_threshold_pct 50` とは
> 一致しないので、**遅延はその分を含めて入力遷移の軸で吸収させている**」。
> `BUFTH` の遅延値を他セルと同じ感覚で読まないこと。
STA 実測では `reg→reg` は不変で `in→reg` だけが増える。

### 方向固定ピンの始末

| 用途 | `HIZ` | `OUT` |
|---|---|---|
| 入力専用 | **VDD に直結** | **開放にしない。VSS に落とす** |
| 出力専用 | **VSS に直結** | コアが駆動 |

`TIEHI`/`TIELO` が無いのでレール直結で配線する。
**入力専用パッドの `OUT` はパッドセル内部で実際にゲート入力になっている**ので、
浮かせると不定。同じ辺で 20 µm 隣にあるリングの GND 端子へ落とすのが定石
（**一周チェーンにしない** — SCLK_SPI は当初リングを一周させて長いルート 4 本とレーン 3 本を無駄にした）。

### 双方向で使うとき

コアが出す出力イネーブルの極性を `HIZ` に合わせて**アクティブ LOW で合成する**のが安い。
SCLK_SPI は `sdio_oe`（アクティブ HIGH）→ `sdio_oe_n` に再合成して
**チップトップに追加セルを 1 個も置かずに済ませた**（コア高 324.9 → 314.1 µm、面積 −3.3%）。
同じ情報を持つ既存の網があるなら直結でよい（DATA 8 本の `HIZ` は `DIS` パッドの網に直結）。

## 5. 電源トポロジ

### 5-1. コア境界に出ている電源（抽出で確認）

| | 露出 |
|---|---|
| **VSS** | **リング全周に M1・M2 両方で露出**。どこからでも接続可。下辺の壁ピンは **y = −920** |
| **VDD** | **上辺の 1 箇所（x = 50〜350 µm）に M1 のタップが 1 本だけ** |

VDD の M2 リングはパッドの**外側**（±1,140 µm）を四辺回るのみで、コア側に出ていない。

M1 タップの実寸: コア境界（y 920〜933）で **300 µm 幅**、その上（y 934〜990）で
**40 µm × 2 本 = 80 µm**。→ **くびれ 80 µm がコア電源の実効入口断面**。

> **⚠ LEF はこれを正しく持っていない。** `TR-1um_frame.lef` の `OSS_FRAME_GIO` の
> `VDD` ピンは `METAL1 (210,920)-(250,990)` と `METAL2 (160,1000)-(240,1080)` の 2 矩形しかなく、
> **40 µm の脚 1 本ぶんだけ**。`VSS` ピンも上辺の M2 矩形 1 個（(−400,920)-(−200,950)）しか
> 書かれておらず、実際の全周露出も下辺の壁ピンも出てこない。
> **電源は必ず GDS を測ること**（SCLK_SPI は VSS の M2 を走査バンドでクリップされた形のまま
> 読んで 12 µm 届かない配線を作った）。

### 5-2. 電流経路は 2 つに分かれる

```
VDD パッド ─┬─ M2 外側リング（四辺）──→ 16 個のパッドセルの VDD
            │                            ← DIO の駆動電流 15.8 mA/本 はここ
            └─ M1 タップ（真下）──→ コア境界 ──→ コアの電源メッシュ
                                              ← コアの電流だけ
```

**DIO の駆動電流はコアの M1 タップを通らない。** したがって M1 タップが運ぶのは
コアのロジック電流だけでよい。**TR-1um の PDK に電流密度／EM の規定は無い**（経験則で判断）。

### 5-3. コア側の構造（この 2 点が設計の前提）

- **TAP2 の縦 M2 ストラップはコア下辺から上辺まで 1 本の連続柱**。
  片端を叩けばカラム全体に効くので、**バスが両端に届く必要がない**
- **リングの VDD ピン(M1) と VSS ピン(M2) は上辺で設計上重なる**。
  ライザーはそこで**M1 のままでビアを置かない** — これが両者を分ける唯一の仕組み。
  **I2C 版はここで M2 側を VDD のバスだと誤認して一度ショートさせている**

### 5-4. 実装パラメータ（SCLK_SPI の値。コア幅に依存するので導出式にすべき → `docs/03_core_geometry.md`）

| | 経路 |
|---|---|
| **VDD** | 上チャネルに幅 **10.0 µm** の M1 バス → 上辺 VDD TAP ピン 4 本を束ね → 幅 **3.4 µm のライザー 9 本**（8.0 µm 間隔）でレーン帯を越え → M1 に乗り換えてリングの VDD 実ピンへ |
| **GND** | 下チャネルに幅 10 µm の M1 バス → コア両側の M2 脚（幅 6.0）を下辺まで下ろす → 幅 10 µm の M1 バスバー → 幅 **10 µm の M2 ストリップ 5 本**（ピッチ 12 = 幅 10 + スペース 2）でフレームの VSS ピンへ |
| `BUS_W` | 10.0 |
| `TAP_STUB_W` | **3.4**（コア自身のストラップ幅と厳密一致） |

> **★ 幅が変わる継ぎ目は実機の幅チェッカーが「ノッチ」として拾う。** スタブ幅はコア側と厳密に合わせる。
> **★ 幅 10 µm の M1 は `M1.SW`（太線間隔 2.0）の境界に乗る**（`docs/10_pdk_facts.md` §3-2）。
> バスバーの周囲は 2.0 µm 空ける。自作チェッカは 1.4 で見るので見逃す。
> **★ 電源 PAD への接続は幅 10 µm × 5 本**。TD4 版の 3.4 µm × 5 本は**電流容量が 1/3** しかなかった。

## 6. リング配線のレーン

コア外縁の外側に、半径方向に等間隔の同心レーンを取り、`T/R/B/L` を閉ループとして扱う。

| 定数 | SCLK_SPI | APR_2026 | 意味 |
|---|---:|---:|---|
| `LANE_R0` | 847.0 | 815.4 | 第 1 レーン半径（**コア幅依存。導出式にすべき**） |
| `LANE_PITCH` | **5.4** | 5.4 | M2 幅 3.4 + M2 最小ギャップ 2.0 ちょうど |
| `NEAR_R` | 915.0 | — | 端子への半径方向ホップ（921.7 の 5 µm 内側） |
| 内壁 | **920.0** | 920.0 | 最上位レーンが避けるべきはここ |
| 実績レーン数 | 13 | 10 | |

**`NEAR_R` は障害物ではない** — 端子への半径方向ホップは後続配線と同一直線上なので場所を取らない。

### 守るべき 3 つの規則（いずれも実際に踏んで得た）

1. **1 ルート = 1 本のポリライン。** 端子への半径方向ホップをリング本体と別の `path` 呼び出しで
   描くと、**角のビアがどちらの呼び出しの持ち物でもなくなり誰も置かない → 全ネット断線**
2. **区間は非ラップの `[min,max]` で取り、向きはその中に収まる方に強制。**
   「全端点を覆う最小の弧」で取ると継ぎ目をまたぐ区間ができ、詰め込みが実在しない配線を前提にする
   → 同一レーンでの短絡
3. **同じネット / 同じ端子は 1 本の幹 + 端点ごとの足にまとめる。**
   APR_2026 移植(21) で 32 本 → 23 群、14 レーン → 10 レーン、総長 −19%

**足の重なり**: 同じ辺で M2 なら 5.4 / M1 なら 3.2 µm 以内に並んだコア側とパッド側の足は、
**パッド側のレーンが外**でないと必ず重なる。`pack()` に下限レーンを渡して解く。

## 7. ボンドパッドの LVS ピン

- **ピンマーカーは 3.0 × 3.0 µm の正方形**（M2PIN 49/1 / M1PIN 48/1）
- **ラベルは TXM2 (49,0) / TXM1 (48,0) にサイズ 20 µm の TEXT を、ピン形状の中心に置く**
  （KLayout のテキスト抽出は「PIN 形状の内側」を要求する）
- ピンマーカーを書く前に**各中心が実メタルの上にあること**を確認する（空中のマーカーは孤立ネットになる）
- **ラベルだけではサブサーキットのピンが生えない。** `add_top_pins.py` は同じ 3 µm 角を
  **M2 (20,0) の実体としても置く**（パッドの M2 に重なるだけなので DRC は変わらずマージされる）。
  これを入れるまで、出力パッド 5 本が PDK 公式 LVS だけで
  `No equivalent pin P<n> … a physical connection is not made` になっていた
- **トップポート数は参照ネットリストと厳密一致必須**。合わないと KLayout はグラフ照合に入らず、
  下位が全部一致していても全ピンが将棋倒しで不一致になる

## 8. チップ取り込み時のセル名

**`OSS_FRAME_GIO` → `OSS_FRAME` に改名してから提出する。**
`scripts/pre_check.py` の `FRAME_CELL_NAMES` は `{OSS_FRAME, OSS_FRAME_TEG}` で
**GIO 版の名前が入っていない**。フレーム GDS には両方入っているが、チップに取り込むのは

`pre_check.py` は「トップセルはちょうど 1 つ」も要求するので、標準セルライブラリ丸ごと読みで
増えた未使用セルを `place_logo.py` が刈る（SCLK_SPI は 17 → 1、62 → 44 セル）。

## 9. ロゴ

| | |
|---|---|
| ビットマップ | `pdk/art/opensusi_logo.txt`、**317 × 63 セル / 5,785 ドット** |
| ドット | **3.0 × 3.0 µm の孤立 M2 正方形**をセル中央に |
| 格子 | **5.0 µm**（= M2 最小幅 3.0 + 最小スペース 2.0） |
| 直交隣接 | 5.0 − 3.0 = **2.0 µm**（M2 最小スペースちょうど → 合法） |
| 斜め隣接 | √2 × 2.0 = 2.83 µm |
| 等倍実寸 | 1,583.0 × 313.0 µm |
| **コメント文字** | **`%`** |

> **★ 塗り潰しブロックで描かない。** I2C v10 は 5 µm 塗り潰しで斜めの角が触れ、手で直す羽目になった。
> **孤立ドットなら状況自体が起きない。**
> **★ コメント文字を `#` にしない。** `#` は ON セルそのものなので、左端が ON の行は `#` で始まる。
> SCLK_SPI では 63 行が 55 行になってロゴが縦に潰れた。
> **★ サイズは決め打ちせずビットマップから実測する**（`logo_size()`）。
