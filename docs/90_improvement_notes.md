## 2. いま残っている技術的負債（優先度順）

### 2-1. ★★★ 設定の 3 層間接と `TD4_*` 環境変数の残存

現状の構造:
```
層1 移植原本（アルゴリズム）  route_channels.py など 20 本超
                             中に `import spi_config as _cfg` と直書き
層2 薄皮                     spi_config.py = `from i2c_config import *`（1 行）
層3 設計固有                 i2c_config.py / td4_config.py
```

「原本を書き換えない＝移植の監査証跡を切らない」という当初の安全策としては正しかった。
しかし実態は既に崩れている:

- SCLK_SPI では**ロジック変更を 5 点**加えており、うち 2 つは `port_rules.py` に
  「コード片の丸ごと差し替え」として入っている（三重引用符を含むためモジュール分離が必要だった）
- `gen_lvs_spice_v9/v10.py` は**置換ルールを諦めて書き直し済み**（「書き換え対象が原本のほぼ
  全域に及ぶため」）
- 一般化が済んだもの（`insert_row_buffers` / `insert_bufth` / `merge_muxdffrb` / 配置系）は
  `i2c_ref/` に**参照として残るだけ**になっている

さらに、config 側の環境変数は `I2C_*` に改名されたのに、**ルータ本体のチューニング用は
`TD4_*` のまま 19 ファイルに残っている**:

```
APR_PRL_MIN_PINS  APR_PRL_NETS  APR_SIDE_BUS_PINS  TD4_FORCE_JOG
APR_RIPUP_AFTER_TOPPINS  APR_TRACK_PITCH  TD4_SPAN_LANE_PACK
APR_COMPONENT_CHECK  APR_SIMPLE_PIN_MAX  APR_STRICT_MAX_TRACKS  TD4_DEBUG_STRICT
APR_PROTECT_PAD  APR_TOPPIN_RIGHT  APR_TOPPIN_ADJACENT_CH  TD4_MACRO_MODE
```

**実質バグ**: `APR_TRACK_PITCH` と `APR_TRACK_PITCH` が二重定義になっており、
**config 側に設定してもルータに届かない**。

→ **決定（2026-09-14）**: 薄皮を廃し `apr/config_base.py` + 各設計 `config.py`。
環境変数は **`APR_*` に統一**し、`cfg.getenv()` 経由に集約する（一覧と作業順は `docs/04_naming.md` §3）。`n_rows == 4` / `protect_y` 空 で原本と完全同一挙動に
なることは SCLK_SPI で確認済みなので、後方互換は担保できる。

### 2-2. ★★★ DRC 値が 4 箇所に散在し、しかも 1 つだけ値が違う

| ファイル | M1 幅/間隔 | M2 幅/間隔 | V1 間隔/囲み |
|---|---|---|---|
| `drc_check.py`（ルータ用） | 1.8 / 1.4 | 3.0 / 2.0 | 1.5 / 1.0（+ V1-GC 1.2） |
| `check_chip.py` の `RULES` | 1.8 / 1.4 | 3.0 / 2.0 | 1.5 / 1.0 |
| **`drc_check_cells.py`** | **1.4** / 1.4 | **1.8** / 2.0 | **1.4** / 1.0 |
| `place_logo.py` | — | 3.0 / 2.0 | — |

セル単体チェックだけ幅ルールが緩い。**これが意図的なのか事故なのか未確定**。
`BUF_X2` の M1 間隔違反（1.300 < 1.400）は間隔ルールなので検出できていたが、
幅ルールで漏れるものがあった可能性がある。

→ **改善**: `apr/rules.py` に 1 本化。差が必要なら「なぜ違うか」をコメントで明示。

### 2-3. ★★ STDCELL が 2 世代 → **v59_4 を正本に決定**（詳細は `docs/02_stdcell_diff.md`）

行高 64.8（SCLK_SPI・29 セル）と 59.4（TD4 / I2C_2026・51 セル）。
**論理セルの幅は完全一致**なので x 方向の前提は共通。違うのは行高と電源ピン名
（`VDD`/`GND` → `vdd`/`vss`）、FF の内部観測ピン追加、Liberty の質。

64.8 版の既知バグ（`BUF_X4`/`BUF_X16` が LEF にあって GDS に無い、`BUF_X2` の
FOREIGN が `BUF_X1` を指していた）は **59.4 版では解消済み**。

`TR-1um_I2C_2026/scripts/pnr/README.md`（64KB / 1,168 行）は **中身が TD4 のまま**。
冒頭が「SCLK_SPI のフローを TD4 に移したもの」で始まり、全編 `td4_config.py` /
`REG8x16` / `MEMPORT` の話。I2C という語は 3 箇所しか出てこない。
同様に `lef/README.md` / `spice/README.md` / `spice/LVS_analysis.md` / `irsim/README.md` も

**結果として APR_2026 の P&R 記録がドキュメント化されていない**（実体は各 `.py` の
docstring と「I2C 移植 (n)」コメントに散っている）。

内容の比率はおおむね **共通 7 : 設計固有 3**。共通部分（移植でルータに入れた変更、
移植 10〜24、短絡潰し、チップレベル）を APRtools の `docs/` に抜き、各リポジトリには
「その設計のフロアプラン決定の経緯と実測値」だけを残すのが妥当。

### 2-6. ★★ ルータが非決定的（根本原因未特定）

同じ配置 JSON（md5 一致）から step6 が **3 短絡 → 0 短絡と揺れた**。
どこかで集合を反復している。対症療法として `route.py` / `place.py` の `__main__` で
`PYTHONHASHSEED=0` を立てて `os.execv` で起動し直している。

**「ルータのどこかで集合を反復している（未特定）」と明記されたまま**。
再現性は MPW 提出物の信頼性に直結するので、APRtools 化のタイミングで潰したい。

関連して:
- `sweep_seed.py` が**最良シードを捨てていた**（短絡 0 のとき `PROBLEM(S) FOUND` が
  出ないのを「配線が落ちた」と誤判定。seed 1 と 9 が 0 件なのに seed 8 の 1 件を
  「最良」と報告）
- import 時に確定する値が 1 つ前の実行を見る（`PER_ROW_LOCAL_NETS` が読む
  `cfg.PLACEMENT_JSON` は stage5 が作り直すので、import 時点では前回のものが残る）

### 2-7. ★★ 検証に死角があり、実際に最終 GDS まで欠陥が残った

**事例 A（SCLK_SPI §14.5）**: スカラーポート 9 本がまるごと未引き出しのまま最終 GDS に残った。
`highlight_top_pins.py` に I2C 設計のポート名が直書きされており、その表に載る
ポートしか探さなかった。バス 16 本だけ偶然一致して通っていた。
**既存の `verify_connectivity_*` はチャネルルータが記録した 44 ネットしか見ず、
ポート→セルピンのスタブ 30 本が死角だった** → `verify_port_connectivity.py` を新設。

**事例 B（APR_2026）**: `drc_check.py` の `TOP_CELL` が渡された GDS に関係なく
コアセル名でハードコードされていた。チップレベル GDS への呼び出しは全部、入れ子の
コアセルだけを見ていたので、**そのセッションの「0 violations」報告は全部無意味**。
ユーザが回した実 KLayout DRC が実違反 50 件を検出。

**事例 C（APR_2026）**: `lvs_pnr.py` は既定で両側 flatten するが PDK デッキは階層で比べる。
`OSS_FRAME_GIO` の **出力パッド 5 本**が「物理的に繋がっていない」と公式ランセットだけが検出。
`klayout_extract.py` はラベル層を M2 に繋ぐので自前チェッカでは 44 ピン全部見えていた。

→ **改善の指針**: 「自前チェッカが 0 を返した」は根拠にならない。
**PDK 公式ランセット（`drc_pdk.py` / `lvs_pdk.py`）を通ることを最終判断にする**という
運用を APRtools の `docs/30_verify_drc_lvs.md` に明文化する。

### 2-8. ★ フレーム幾何がチップ配線スクリプトに直書き

`route_chip.py` に 30 個以上（`R_NOM` `LANE_R0` `LANE_PITCH` `NEAR_R` `TIE_R`
`VDD_BUS_Y` `GIO_VDD_PIN` `VDD_CROSS_Y` `VDD_RISER_*` `GND_LEG_X` `GND_BOT_BUS_Y`
`GIO_VSS_PIN_Y` `VSS_STRIP_*` `GND_RING_PINS` `BUS_W` `TAP_STUB_W`）。
これは `OSS_FRAME_GIO` の物理的性質であって設計固有ではない。

しかも `LANE_R0 = 847.0` は「コア端 816.3 の 30.7 µm 外」＝ **コア幅 1620 固定に依存**。
コア幅が変わると破綻する。`VDD_BUS_Y = 838.0` も同様にコア位置依存。

→ **改善**: `frame_pins.py` が 42 端子を実読みしているのと同じ思想で、
「フレーム記述オブジェクト + コア幾何からの導出」に。

### 2-9. ★ `spi_config` / `*` 等の命名に設計の痕跡 → **剥がすことに決定**

`nrow` = N 行、`fm` = Fiduccia–Mattheyses。移植世代の痕跡で、いまや全スクリプトが
N 行対応・FM 分割なので情報量がゼロ。実測で **22 ファイル / 約 130 箇所**。

`TOP_CELL_NAME` は全スクリプトが既に `_cfg.TOP_CELL_NAME` 経由で、リテラルは config の 1 行だけ
（確認済み）。JSON パスも config 1 箇所に集約済み。**改名の影響範囲は思ったより小さい。**

→ **決定**: 剥がす。ただし**既提出設計（SCLK_SPI / TD4 / APR_2026）のトップセル名は変えない**
（`simulation/<セル名>.spice` の探索規約と `.extracted` が連動するため）。
改名表と手順は `docs/04_naming.md` §2。

### 2-12. ★ 電源ピン名が 3 つの名前空間で混在 → **`vdd`/`vss` に統一と決定**

| 層 | 現在 |
|---|---|
| セルピン（v59_4） | `vdd` / `vss` |
| コアのトップピン・ラベル | `VDD` / `GND` |
| フレーム / ボンドパッド | `VDD` / `VSS` |

`I2C_2026/scripts/pnr/*.py` のリテラル実測: `"VDD"` 49 / `"GND"` 45 / `"VSS"` 17 /
`"vdd"` 15 / `"vss"` 16。**セルは既に小文字なのにスクリプトは大文字のまま**。

→ **決定**: 自作フローが名前を決める場所は全て **`vdd` / `vss`**。`GND` は使わない。
フレーム由来の `VDD`/`VSS` は変更不可。`apr/rules.py` の定数経由にする。
**SPICE は大小を区別しない**ので LVS は壊れないが、**大小だけで別ネットを作れない**ことに注意
（TD4 メモリ LVS 第 5 回の `web` / `WEB` 短絡）。詳細は `docs/04_naming.md` §1。

### 2-10. ★★ SCLK_SPI の TAP 間隔が実測ピッチを 5.4 µm 超えている

`placement.json` から実際の TAP 位置を読み出して検算した結果:

| 設計 | 行幅 | TAP x | 間隔 | 判定 |
|---|---:|---|---|---|
| APR_2026 / TD4 | 1598.4 | 0 / 534.6 / 1069.2 / 1587.6 | 534.6, 534.6, **518.4** | OK |
| **SCLK_SPI** | **1620.0** | 0 / 534.6 / 1069.2 / **1609.2** | 534.6, 534.6, **540.0** | **超過 +5.4 µm** |

DRC は通る（TAP 密度は PDK の DRC ルールではない）が、基板/ウェル電位の取り方としては
設計意図から外れている。TD4 が 1620 を捨てて 1598.4 にしたのはこれを避けるため。

TAP 列数 n で成立する条件は `W ≤ (n-1)×534.6 + 10.8`。**4 列で取れるコア幅の上限は
1614.6 µm（= 5.4 × 299 トラック）**。1620.0（300 トラック）は 4 列では成立しない。

→ **改善**: `check()` に「`tap_columns()` の最大間隔 ≤ `TAP_PITCH`」を追加して
import 時に弾く。詳細と導出は `docs/03_core_geometry.md`。

### 2-11. ★ コア幾何がリテラルでコピーされている

`CORE_OFFSET_X = -CORE_WIDTH_UM / 2` は既存 2 世代で厳密に成立している
（SPI 1620.0 → −810.0、I2C 1598.4 → −799.2）。つまり**すでに事実上の規約**なのに、
値だけが各 config にコピーされていた。`TAP_X_DEFAULT` も 4 要素のリテラル、
`LANE_R0` も 847.0 / 815.4 / 810.0 とベタ書き。

→ **決定**: コア幅を `CORE_WIDTH_TRACKS`（トラック本数）1 個でパラメータ化し、
オフセット・チップ座標・TAP 列・レーン開始半径は全て導出式にする。

## 3. 設計をまたいで再発した失敗（=「穴」として共通ドキュメント化すべきもの）

同じ罠を 2 回以上踏んでいるものを優先で並べる。

| # | 穴 | 踏んだ回 | 対策 |
|---|---|---|---|
| 1 | **LVS のトップポート本数が合わないと、KLayout はグラフ照合に入らず全ピンが将棋倒しで不一致になる** | I2C(2本落として)、TD4、SPI | ポート数を参照ネットリストと厳密一致させる。数が合わない時点で中身を見ても無駄 |
| 2 | **ラベルだけではサブサーキットのピンが生えない** | I2C_2026（出力パッド 5 本） | ピンマーカーの M2 実体も置く。ラベルは (48,0)/(49,0) だけが読まれる |
| 3 | **`.control` に `run` を書くと解析が 2 回走る。`print` を書くと 2 回目が本当に壊れる** | I2C v10、SPI | `.control` は `save` を置くためだけに使う |
| 4 | **ngspice の Tmax 50 ns では 10 ns 未満のセットアップ余裕を解像できない** | I2C（数セッション溶かした）、SPI | **Tmax = 1 ns 固定**。10/14 → 14/14 になった |
| 5 | **1 ルート = 1 本のポリライン。別の `path` 呼び出しに分けると角のビアが誰の持ち物でもなくなり全ネット断線** | SPI（リング、GND 脚で 2 回） | 区間は非ラップの `[min,max]`、向きはその中に収まる方に強制 |
| 6 | **リングの VDD ピン(M1) と VSS ピン(M2) が上辺で重なる** | **I2C 版はここで M2 側を VDD と誤認して一度ショートさせた** | ライザーは M1 のままでビアを置かない。それが両者を分ける唯一の仕組み |
| 7 | **幅が変わる継ぎ目は実機の幅チェッカーがノッチとして拾う** | I2C 79.8、SPI（VDD ライザー） | `TAP_STUB_W` はコア側ストラップ幅と厳密一致 |
| 8 | **ロゴを塗り潰しブロックで描くと斜め接触を手で当てる羽目になる** | I2C v10 | **3.0 µm 角の孤立ドット / 5.0 µm 格子**なら状況自体が起きない |
| 9 | **ロゴビットマップのコメント文字を `#` にすると ON セルの行が黙って消える** | SPI（63 行 → 55 行） | コメントは `%` |
| 10 | **KLayout LVS は階層のままの MUXDFFRB を照合できない** | I2C §108.45（NoMatch/Skipped）、SPI | `x1_`/`x2_` プレフィックスで展開 |
| 11 | **素子数で比較してはいけない**（折り畳み / デキャップ / `m=2`） | I2C、SPI §15.4 | 折り畳み不変量（PMOS 総幅・NMOS 総幅・L）で比較 |
| 12 | **SPICE は大文字小文字を区別しない** → `web` と `WEB` が同一ネットに潰れて短絡に見える | TD4 メモリ LVS 第5回 | 内部線を `WEBI` に改名 |
| 13 | **`combine_devices()` が DFFRB で KLayout 内部エラー** | TD4、APR_2026 | 両側とも combine を掛けない。フレームは `--no-combine` 版を使う |
| 14 | **LVS 用の `_lay.spice` は ngspice に使えない**（ポート無し・番号ネット・`M` vs `XM`） | TD4、APR_2026、SPI | `klayout_extract.py` 経由で別に作る |
| 15 | **`.extracted` を素の `NetlistSpiceReader` で読むと device 0 に見える** | TD4、APR_2026 | デリゲートが要る |
| 16 | **LEF の OBS を設計の根拠に使わない**（四隅を粗く塞いで「実在しない崖」を作る） | TD4（`CORE_WIDTH_UM=1598.4` はこの崖を避けた値） | `frame_opening()` で実ジオメトリを二分探索実測 |
| 17 | **step5（配置 JSON 変換）を忘れると前の設計の配置で配線が回る** | SPI §16.8、TD4 | `route.py` の stage5 に取り込み済み |
| 18 | **`squeeze` がトップ辺の PIN マーカーを高さ 0 に潰す** | SPI（18 個） | `protect_y` で保護。コアが 3.0 µm 高くなるのは許容 |

### 6-1. 世代差の取り込み（SCLK_SPI に入っていない改良）

| STDCELL v59_4 | 行高 −8.3%、`INV_X2`、実特性化 Liberty | コア面積縮小 + 合成品質向上 |

### 6-2. SCLK_SPI 固有で引き継ぐべき設計判断

- **`ROW_WIDTH_UM = 1620.0` は設計パラメータではなくフレーム側の要請**。
  `CORE_OFFSET_X = -810.0` でコアをチップ軸に対称にするための値（コアの native bbox
  −6.3..1626.3 → ±816.3）。`LANE_R0 = 847.0` もここが起点。
  **「行幅は共通規約、行数だけが設計固有」**という整理が実態に近い。
  ただし APR_2026 は `CORE_WIDTH_UM = 1598.4` を採用している（1620 だと TAP 4 本の
  最後の間隔が 540.0 になり実測ピッチ 534.6 を超えるため）。**再設計時にどちらに合わせるか要決定**。
- **`sdio_oe_n` はアクティブ LOW**（option C）。`HIZ2` に直結でき、チップトップに追加セルが 1 個も要らない。
  コア高 324.9 → 314.1 µm、面積 −3.3%。`tb_06_tristate` の期待値は反転済み。
- **入力専用パッドの `OUT` ピンは開放にしない**（パッドセル内部で実際にゲート入力）。
  同じ辺で 20 µm 隣のリング GND 端子に落とす。
- **`DIS` は CS=Low 中に変化させてはならない**（`shift_clk = SCLK ^ DIS` にグリッチ）。
- **Mode 0 違反の対策（`msb_done` FF）を消さないこと**。`tb_05_mode0` のみが検出する。
  コスト `DFFRB`×1 + `OR3`×1 − `NOR3`×1 ≈ +28 Tr。
- **クロック分配の確認項目**: 2 行構成では 1 つの行バッファが最大 1.29 mm の行全体の
  FF クロックピンを駆動。**クロック枝は配線容量支配**。`BUF_X2`（W=20.4/6.8 µm）で
  足りるかは**レイアウト抽出後の SPICE で確認**。足りなければ `BUF_X4` の実装が素直。

### 6-3. 再設計の前提（2026-09-14 決定）

1. **STDCELL は v59_4**。行高 64.8 → 59.4（−8.3%）、電源ピン名が `vdd`/`vss` に、
   Liberty が実特性化版に、`INV_X2` / `FILL1` が使える。
   → 電源ピン名の小文字化が全スクリプトに波及するので `apr/rules.py` に寄せてから一括変換
2. **コア幅は `CORE_WIDTH_TRACKS × 5.4`**。**1620.0（300 トラック）は使わない**
   （TAP 最終間隔が 540.0 になり実測ピッチ 534.6 を超える）。
   候補は **296 トラック = 1598.4**（I2C/TD4 実績）か **299 トラック = 1614.6**（4 列での最大）
3. コア幅が変わるので `CORE_OFFSET_X` `LANE_R0` `VDD_BUS_Y` など `route_chip.py` の
   リテラルはそのまま使えない。**導出式に置き換えるのが再設計の前提作業**
4. `ROUTE_CH_HEIGHTS` は行高が変わるので再測定。`CH_HEIGHTS` の上下端は **5.4 の倍数**にすること
   （131.6/153.2 のままだと M1 間隔違反 3 件が step10 まで残る — APR_2026 の実測）
5. `FILL1` を既定で有効にするか要判断（コア幅が 5.4 刻みになる以上、有効が筋。
   ただし配置が丸ごと変わるので seed 掃引で比較）

### 6-4. まだ決めていないこと

1. `TOP_CHANNEL_UM` を 90.0 のままにするか（100 に上げると 18 トラック、コアが下がるだけで
   下側は空いている）
2. RING_OSC / ロゴの縦積みを SPI にも入れるか（APR_2026 は入れている）
