## 2. 構造上の技術的負債（2026-09-14 の棚卸し）

各節の先頭に**いまの状態**を足してある。本文は当時のまま。

### 2-1. ★★★ 設定の 3 層間接と `TD4_*` 環境変数の残存

> **状態: 決着**（決定 3 / U29 / U26）。薄皮を廃して `apr/config_base.py` + 各設計 `config.py` に、環境変数は `APR_*` + `ENV_KNOBS` 台帳に。**残っているのは U5**（`APR_TRACK_PITCH` を 2 箇所が別々に読む）。

現状の構造:
```
層1 移植原本（アルゴリズム）  route_channels.py など 20 本超
                             中に `import spi_config as _cfg` と直書き
層2 薄皮                     spi_config.py = `from i2c_config import *`（1 行）
層3 設計固有                 i2c_config.py / td4_config.py
```

「原本を書き換えない＝移植の監査証跡を切らない」という当初の安全策としては正しかった。
しかし実態は既に崩れている:

- SCLK_SPI では**ロジック変更を 5 点**加えており、うち 2 つは `port_rules.py` に
  「コード片の丸ごと差し替え」として入っている（三重引用符を含むためモジュール分離が必要だった）
- `gen_lvs_spice_v9/v10.py` は**置換ルールを諦めて書き直し済み**（「書き換え対象が原本のほぼ
  全域に及ぶため」）
- 一般化が済んだもの（`insert_row_buffers` / `insert_bufth` / `merge_muxdffrb` / 配置系）は
  `i2c_ref/` に**参照として残るだけ**になっている

さらに、config 側の環境変数は `I2C_*` に改名されたのに、**ルータ本体のチューニング用は
`TD4_*` のまま 19 ファイルに残っている**:

```
APR_PRL_MIN_PINS  APR_PRL_NETS  APR_SIDE_BUS_PINS  TD4_FORCE_JOG
APR_RIPUP_AFTER_TOPPINS  APR_TRACK_PITCH  TD4_SPAN_LANE_PACK
APR_COMPONENT_CHECK  APR_SIMPLE_PIN_MAX  APR_STRICT_MAX_TRACKS  TD4_DEBUG_STRICT
APR_PROTECT_PAD  APR_TOPPIN_RIGHT  APR_TOPPIN_ADJACENT_CH  TD4_MACRO_MODE
```

**実質バグ**: `APR_TRACK_PITCH` と `APR_TRACK_PITCH` が二重定義になっており、
**config 側に設定してもルータに届かない**。

> ★ **この行は原文のまま**（同じ名前が 2 回書かれているのは当時の書き間違い）。
> 実態は「**同じ環境変数を `config_base.py` と `route_channels.py` が別々に読む**」で、
> いまはどちらも `rules.TRACK_PITCH` を既定にしているので値はずれない。**U5 として残っている**。

→ **決定（2026-09-14）**: 薄皮を廃し `apr/config_base.py` + 各設計 `config.py`。
環境変数は **`APR_*` に統一**し、`cfg.getenv()` 経由に集約する（一覧と作業順は `docs/04_naming.md` §3）。`n_rows == 4` / `protect_y` 空 で原本と完全同一挙動に
なることは SCLK_SPI で確認済みなので、後方互換は担保できる。

### 2-9. ★ `spi_config` / `*` 等の命名に設計の痕跡 → **剥がすことに決定**

> **状態: 決着**（決定 7 / U44）。トップセル名は `selfcheck` が形まで見る。

`nrow` = N 行、`fm` = Fiduccia–Mattheyses。移植世代の痕跡で、いまや全スクリプトが
N 行対応・FM 分割なので情報量がゼロ。実測で **22 ファイル / 約 130 箇所**。

`TOP_CELL_NAME` は全スクリプトが既に `_cfg.TOP_CELL_NAME` 経由で、リテラルは config の 1 行だけ
（確認済み）。JSON パスも config 1 箇所に集約済み。**改名の影響範囲は思ったより小さい。**

→ **決定**: 剥がす。ただし**既提出設計（SCLK_SPI / TD4 / APR_2026）のトップセル名は変えない**
（`simulation/<セル名>.spice` の探索規約と `.extracted` が連動するため）。
改名表と手順は `docs/04_naming.md` §2。

### 2-12. ★ 電源ピン名が 3 つの名前空間で混在 → **`vdd`/`vss` に統一と決定**

> **状態: 決着**（決定 6 / U11 / U21 / U27）。写像は `rules` に 1 つだけ。

| 層 | 現在 |
|---|---|
| セルピン（v59_4） | `vdd` / `vss` |
| コアのトップピン・ラベル | `VDD` / `GND` |
| フレーム / ボンドパッド | `VDD` / `VSS` |

`I2C_2026/scripts/pnr/*.py` のリテラル実測: `"VDD"` 49 / `"GND"` 45 / `"VSS"` 17 /
`"vdd"` 15 / `"vss"` 16。**セルは既に小文字なのにスクリプトは大文字のまま**。

→ **決定**: 自作フローが名前を決める場所は全て **`vdd` / `vss`**。`GND` は使わない。
フレーム由来の `VDD`/`VSS` は変更不可。`apr/rules.py` の定数経由にする。
**SPICE は大小を区別しない**ので LVS は壊れないが、**大小だけで別ネットを作れない**ことに注意
（TD4 メモリ LVS 第 5 回の `web` / `WEB` 短絡）。詳細は `docs/04_naming.md` §1。

### 2-10. ★★ SCLK_SPI の TAP 間隔が実測ピッチを 5.4 µm 超えている

> **状態: 決着**（U15）。★ **前提が違った** — 534.6 は PDK の規則ではなく自前の慣習値。既提出は触らない。

`placement.json` から実際の TAP 位置を読み出して検算した結果:

| 設計 | 行幅 | TAP x | 間隔 | 判定 |
|---|---:|---|---|---|
| APR_2026 / TD4 | 1598.4 | 0 / 534.6 / 1069.2 / 1587.6 | 534.6, 534.6, **518.4** | OK |
| **SCLK_SPI** | **1620.0** | 0 / 534.6 / 1069.2 / **1609.2** | 534.6, 534.6, **540.0** | **超過 +5.4 µm** |

DRC は通る（TAP 密度は PDK の DRC ルールではない）が、基板/ウェル電位の取り方としては
設計意図から外れている。TD4 が 1620 を捨てて 1598.4 にしたのはこれを避けるため。

TAP 列数 n で成立する条件は `W ≤ (n-1)×534.6 + 10.8`。**4 列で取れるコア幅の上限は
1614.6 µm（= 5.4 × 299 トラック）**。1620.0（300 トラック）は 4 列では成立しない。

→ **改善**: `check()` に「`tap_columns()` の最大間隔 ≤ `TAP_PITCH`」を追加して
import 時に弾く。詳細と導出は `docs/03_core_geometry.md`。

### 2-11. ★ コア幾何がリテラルでコピーされている

> **状態: 決定済み**（決定 5 / U17）。コア幅は `CORE_WIDTH_TRACKS × 5.4`、296 トラックのまま。

`CORE_OFFSET_X = -CORE_WIDTH_UM / 2` は既存 2 世代で厳密に成立している
（SPI 1620.0 → −810.0、I2C 1598.4 → −799.2）。つまり**すでに事実上の規約**なのに、
値だけが各 config にコピーされていた。`TAP_X_DEFAULT` も 4 要素のリテラル、
`LANE_R0` も 847.0 / 815.4 / 810.0 とベタ書き。

→ **決定**: コア幅を `CORE_WIDTH_TRACKS`（トラック本数）1 個でパラメータ化し、
オフセット・チップ座標・TAP 列・レーン開始半径は全て導出式にする。

## 3. 設計をまたいで再発した失敗（=「穴」として共通ドキュメント化すべきもの）

同じ罠を 2 回以上踏んでいるものを優先で並べる。

| # | 穴 | 踏んだ回 | 対策 |

| 1 | **LVS のトップポート本数が合わないと、KLayout はグラフ照合に入らず全ピンが将棋倒しで不一致になる** | I2C(2本落として)、TD4、SPI | ポート数を参照ネットリストと厳密一致させる。数が合わない時点で中身を見ても無駄 |

## 6. SCLK_SPI 再設計への申し送り

### 6-1. 世代差の取り込み（SCLK_SPI に入っていない改良）

| 由来 | 内容 | 効果 |
|---|---|---|
| APR_2026 移植(11) | **配置のパッド近接項**（`cut_cost` と `hpwl` の両方に `_EDGE_ROW` 重み） | リング配線の回り込みを削減。I2C では seed 4 / 重み 16 |
| APR_2026 移植(12) | **トップピンをピンの x で近い辺へ振り分け** | 行単位振り分けによる長距離トランク → 短絡を防ぐ |

| APR_2026 | `CH_HEIGHTS` の上下端を **5.4 の倍数**にする | 131.6/153.2 のままだと M1 間隔違反 3 件が step10 まで残る |
| STDCELL v59_4 | 行高 −8.3%、`INV_X2`、実特性化 Liberty | コア面積縮小 + 合成品質向上 |

### 6-2. SCLK_SPI 固有で引き継ぐべき設計判断

- **`ROW_WIDTH_UM = 1620.0` は設計パラメータではなくフレーム側の要請**。
  `CORE_OFFSET_X = -810.0` でコアをチップ軸に対称にするための値（コアの native bbox
  −6.3..1626.3 → ±816.3）。`LANE_R0 = 847.0` もここが起点。
  **「行幅は共通規約、行数だけが設計固有」**という整理が実態に近い。
  ただし APR_2026 は `CORE_WIDTH_UM = 1598.4` を採用している（1620 だと TAP 4 本の
  最後の間隔が 540.0 になり実測ピッチ 534.6 を超えるため）。**再設計時にどちらに合わせるか要決定**。
- **`sdio_oe_n` はアクティブ LOW**（option C）。`HIZ2` に直結でき、チップトップに追加セルが 1 個も要らない。
  コア高 324.9 → 314.1 µm、面積 −3.3%。`tb_06_tristate` の期待値は反転済み。
- **入力専用パッドの `OUT` ピンは開放にしない**（パッドセル内部で実際にゲート入力）。
  同じ辺で 20 µm 隣のリング GND 端子に落とす。
- **`DIS` は CS=Low 中に変化させてはならない**（`shift_clk = SCLK ^ DIS` にグリッチ）。
- **Mode 0 違反の対策（`msb_done` FF）を消さないこと**。`tb_05_mode0` のみが検出する。
  コスト `DFFRB`×1 + `OR3`×1 − `NOR3`×1 ≈ +28 Tr。
- **クロック分配の確認項目**: 2 行構成では 1 つの行バッファが最大 1.29 mm の行全体の
  FF クロックピンを駆動。**クロック枝は配線容量支配**。`BUF_X2`（W=20.4/6.8 µm）で
  足りるかは**レイアウト抽出後の SPICE で確認**。足りなければ `BUF_X4` の実装が素直。

### 6-3. 再設計の前提（2026-09-14 決定）

1. **STDCELL は v59_4**。行高 64.8 → 59.4（−8.3%）、電源ピン名が `vdd`/`vss` に、
   Liberty が実特性化版に、`INV_X2` / `FILL1` が使える。
   → 電源ピン名の小文字化が全スクリプトに波及するので `apr/rules.py` に寄せてから一括変換
2. **コア幅は `CORE_WIDTH_TRACKS × 5.4`**。**1620.0（300 トラック）は使わない**
   （TAP 最終間隔が 540.0 になり実測ピッチ 534.6 を超える）。
   候補は **296 トラック = 1598.4**（I2C/TD4 実績）か **299 トラック = 1614.6**（4 列での最大）
3. コア幅が変わるので `CORE_OFFSET_X` `LANE_R0` `VDD_BUS_Y` など `route_chip.py` の
   リテラルはそのまま使えない。**導出式に置き換えるのが再設計の前提作業**
4. `ROUTE_CH_HEIGHTS` は行高が変わるので再測定。`CH_HEIGHTS` の上下端は **5.4 の倍数**にすること
   （131.6/153.2 のままだと M1 間隔違反 3 件が step10 まで残る — APR_2026 の実測）
5. `FILL1` を既定で有効にするか要判断（コア幅が 5.4 刻みになる以上、有効が筋。
   ただし配置が丸ごと変わるので seed 掃引で比較）

### 6-4. まだ決めていないこと

1. `TOP_CHANNEL_UM` を 90.0 のままにするか（100 に上げると 18 トラック、コアが下がるだけで
   下側は空いている）
2. RING_OSC / ロゴの縦積みを SPI にも入れるか（APR_2026 は入れている）

## 7. 台帳（U1–U84）

**読み方。**

- 番号 `U<n>` は通し番号で、**一度振ったら変えない**（`apr/*.py` と他の docs が引く）。
- 状態は 4 つ: **未解決** / **判断待ち**（設計者の判断が要る）/ **一部残**
  （主要部は決着したが残りがある）/ **決着 &lt;日付&gt;**。
  ★ **取り消し線では状態を表さない。** 機械で数えられないし、

  誰も踏まない。
- **読めない出典を根拠として引かない**（U52 / U66 / U75）。
- **同じ道具が 3 設計で作るものは、3 設計で同じ扱いにする**（U83 — 生成物の受け皿が
  1 設計にしか無かった）。★ ただし **和集合にしない**。追跡済みのファイルに当たる規則は、
  足しても追跡が外れず「無視されているのに履歴にある」状態を作る。
- ★ **移してきた道具が、移す前から動いていたと決めてかからない**（U80 — `check_top_channels.py` は元の場所でも動かず、2 世代前のプランの形を読んでいた）。
  **移植先で 1 度通してから「移した」と書く。**

### 8-4. 測り方

- ★ **点で測らない。窓で測る。** 内部の遅れは条件で変わるので、サンプル時刻を決め打ちすると
  「まだ立っていない」を掴む（U2 で 4 回踏んだ）。
- ★ **線形外挿しない。** 広い条件で測った遅れを境界に当てはめると外れる
  （U7 — 内部 `WR` は幅が狭いと満振れせず、遅れ自体が変わる）。
- **切り分けの単位を「差分」ではなく「回路の段」に取る**（U2）。
- **つまみを足したら、それに依存する時刻も直す。** 掃引の端で刺激が壊れていないかを必ず見る
  （U2 — 壊れた PWL のまま「保持する」と出ていた）。
- **寸法は GDS を測る。** 中間ファイルの数字は「予算」であって成果物ではない（U45）。
- **素子数で比較しない**（折り畳み / デキャップ / `m=2`。穴 11 / U49）。
  **大きさの違うセルが同じ数なら、数え方が壊れている合図。**
- **手で消して回した実験は再現できない。** 切り分けは道具に入れる（U69 の `--strip` / `--web-*`）。

### 8-5. 手順書

- **仮名は本物に見える偽物。** 手順のコマンドは**貼ったら落ちる形**（山括弧）にする
  （U35 の続き 2 — `~/HogeHoge/…` をそのまま貼って `No such file or directory`）。
- **`cd -` を書かない**（2 回続けて打つと戻る）。サブシェル `( cd dir && cmd )` にする。
- **行末に `#` の注釈を付けない**（zsh は既定で行末コメントを取らない）。
- **手順書に「その場の状態に依存する書き方」を残さない。**
- **直したときは手順書も見る**（`docs/31` が U24 以前の説明のまま残っていた）。

### 8-6. 値と前提

- **寸法を決めた前提を、値の隣に書く**（U46 / U48 — 前提が変わったときに気づけない）。
- **「規則を超えている」と「規則がある」は別**（U15 — 534.6 は PDK の規則ではなかった）。
- **値ではなく意味で選ぶ**（U62 — `lint --constants` は「値が同じ」としか言えない）。
- **既定値は「最良」ではなく「この値で通った」**（U61）。
