## 1. プロセス諸元

| 項目 | 値 | 出典 |
|---|---|---|
| ノード | 1 µm CMOS, N-well (`WN`) | `Manifesto.md` |
| 最小ゲート長 L | **1.0 µm**（レンジ 1.0–30.0） | `AP.LM` / `AN.LM` |
| 最小ゲート幅 W | **3.4 µm**（レンジ 3.4–60.0） | `AP.WM` / `AN.WM` |
| Tox | 19.5 nm → **5 V 系** | `models_IP62_mos_v2.lib` |
| Vth | NMOS +0.763 V / PMOS −0.678 V | 同上 |
| 配線層 | **M1 / M2 の 2 層のみ**（+ ポリ GC、V1、CO） | DR Table |
| Drawing layer | **8 層**（従来 17 マスク + 6 認識層を簡素化） | `Manifesto.md` |
| デバイス | NMOS/PMOS（通常・空乏型）、抵抗 RR/RS、容量 CSIO、ダイオード | models |
| dbu | 0.001 µm（`MANUFACTURINGGRID 0.1`） | `TR-1um_tech.lef` |

**配線が 2 層しかないことが自作 P&R を書いた直接の理由**。一般的な OSS フローは 3 層以上を前提にする。

Mask layer は最終段の **MDP**（Mask Data Preparation）で Drawing layer から自動生成される。
設計者が触るのは Drawing layer だけ。MDP は `run_mdp.drc` → `run_IP62.drc`。

|---|---:|---|
| M1 最小幅 | **1.8** | `M1.W1` |
| M1 最小間隔 | **1.4** | `M1.S1` |
| M2 最小幅 | **3.0** | `M2.W1` |
| M2 最小間隔 | **2.0** | `M2.S1` |
| V1 カット寸法 | **1.4 角ちょうど**（幅・bbox_min・bbox_max すべて） | `V1.W1` |
| V1 最小間隔 | **1.5** | `V1.S1` |
| V1 の M1 囲み | **1.0** | `V1.M1` |
| M2 の V1 囲み | **1.0** | `M2.V1` |

### 3-2. ★ 自作チェッカが実装していない BEOL ルール

| **`M1.W3` / `M2.W3`** | **M1 / M2 の最大幅 45.0 µm**（パッド部 `M1P`/`M2P` と `AC` は除外） | `sized(-22.5).sized(22.5)` |
| **`ERR01`** | **製造グリッド 0.050 µm**（`WN AP AN AR AC GC GR CO M1 V1 M2 PO` の **12 層すべて**） | `(<層>).ongrid(0.050)` |
| `ERR00` | `PTECT` の上に `V1` / `M2` / `PO` を置かない | |
| `ERR02` | ねじれポリゴン（`odd_polygons`） | |
| `M1.SCR` / `M2.SCR` | スクライブ領域の M1/M2 は本体 M1/M2 と 5.0 間隔 | |
| `M1P.PE` / `M2P.PE` | パッドの引き出しは 14 µm にわたり 40 µm 幅が必要 | |

| `M1.CO` / `M1.CC` / `M1.CL` | M1 の CO 囲み 0.8 / 1.3 / 1.2 | |

`M1W` の定義は `M1.sized(-5.0).merged.sized(5.0).merged`。

### 3-2a. `M1.SW` の判定境界（U18。**デッキで確認済み** 2026-09-17）

**ちょうど 10.000 µm は `M1(W)` ではない。** `sized(-5.0)` が幅 10.000 を幅 0 に潰し、
面積 0 の図形が消えるため。**10.000 を超えると** `M1(W)` になる。

**デッキ（KLayout 0.30.9）に探針を通した結果**:

| セル | 幅 | デッキの出力 |
|---|---:|---|
| `T_SW_10` | **10.000** | **違反 0 件** |
| `T_SW_10p` | **10.050** | **`M1.SW` 1 件** |
| `T_SW_TEE` | 10.000 の T 字 | **違反 0 件** |

同じ幅のバーが直交して刺さる T 字でも、角は 10 × 10 なので `-5.0` で点になり、
**10.000 のままなら `M1(W)` にならない**。

★ **余裕は 1 dbu ではなく製造グリッド 1 つ分（0.050 µm）。** 最初この探針を
10.001（1 dbu）で作ったところ、デッキは `M1.SW` に加えて **`ERR01: OFFGRID 0.050` を
6 件**出した。`01_Basics.drc` が 12 層すべてに `ongrid(0.050)` を掛けているので、
**0.001 の刻みはそもそも作れない**。10.0 の次に作れる幅は 10.050 である。

> **⚠ 実務上の注意**: 電源バー（`CHIP_BUS_W` / `POWER_BAR_W` / `RO_VSS_BAR_W`）は
> **幅ちょうど 10.000 µm** で、`M1(W)` の**内側**にいる。合法で、
> **作れる刻みで 1 つ分（0.050 µm）の余裕**がある。
>
> ★ **`POWER_BAR_GAP = 2.0` は周囲との間隔ではない。** あれは**ストラップ 2 本の間**の
> 隙間で、`connect_macro_power.py` が周りとの空きを見るのは `M1_MIN_GAP`（= 1.4）である。
> 提出済み GDS の実測では、**TD4 でストラップの 1.8 µm 上を幅 3.4 の M1 レールが走る箇所が 2 つ**
> あり、**幅を 1 dbu でも増やすと `M1.SW` が 2 件出る**（I2C / SPI は 0）。
> 幅を触るなら `M1_MIN_GAP` を 2.0 にするのが先。
>
> 自作チェッカ（`drc_check.py` / `check_chip.py`）は M1 間隔を一律 1.4 で見るので、
> **バー周りの 1.4〜2.0 µm の違反を見逃す**。最終判断は必ず `drc_pdk.py`（PDK 公式デッキ）で取る。

### 3-3. FEOL で P&R に効くもの

| ルール | 値 | DR 名 |
|---|---:|---|
| GC 最小幅（= 最小ゲート長） | 1.0 | `GC.W1` |
| GC 最小間隔 | 1.2 | `GC.S1` |
| CO 寸法 | 1.0 角固定 | `CO.W1` / `CO.WM` |
| CO 最小間隔 | 1.0 | `CO.S1` |
| WN 最小幅 / 間隔 | 8.0 / 4.0 | `WN.W1` / `WN.S1` |
| AP/AN の WN 囲み | 7.0 / 5.0 | `AP.WN` / `AN.WN` |

`WN.S1 = 4.0` と `AP.WN = 7.0` が、**セルの prBoundary から N-well が x 方向に +6.3 µm、
y 方向に +4.0 µm はみ出す**理由。行の中でセルをアバットさせると隣とマージされる。

## 4. 配線グリッド（`TR-1um_tech.lef` と実測）

```
SITE TR1UM      CLASS CORE ; SYMMETRY Y ; SIZE 5.4 BY 59.4 ;
LAYER METAL1    DIRECTION HORIZONTAL ; PITCH 3.2 ; WIDTH 1.8 ; SPACING 1.4 ;
LAYER METAL2    DIRECTION VERTICAL   ; PITCH 5.4 ; OFFSET 2.7 ; WIDTH 3.4 ; SPACING 2.0 ;
LAYER VIA1      TYPE CUT ; SPACING 1.4 ;
VIA V1_1x1      M1 -1.7..1.7 / V1 -0.7..0.7 / M2 -1.7..1.7
```

| 定数 | 値 | 導出 |
|---|---:|---|
| サイト幅 `SITE_UM` | **5.4** | ポリピッチ |
| 行高 `ROW_HEIGHT_UM` | **59.4**（v59_4） | prBoundary 実測、論理セル 39 個すべて |
| トラックピッチ `TRACK_PITCH` | **5.4** | 下記 |
| `TRACK0_OFFSET` | 2.0 | |
| セル内 M2 トラック | prBoundary 左端から **2.7 + n × 5.4** | LEF `OFFSET 2.7` |
| via_1 の M1/M2 パッド | **3.4 角** | `V1_1x1` の ±1.7 |

**トラックピッチ 5.4 が下限である理由**（実測で確認済み）:
via_1 は M1 と M2 の両方に 3.4 角のパッドを置く。隣接トラックの via が同じ x に来たときの拘束は

```
M1: 3.4 + 1.4 = 4.8
M2: 3.4 + 2.0 = 5.4   ← こちらが効く
```

5.0 にすると M2 間隔違反がちょうど `dy=1.6 dx=3.4` で出る（M1 も 11 件）。
`route_channels.py` が下限を検査して `SystemExit` する。

> **⚠ LEF の `METAL2 PITCH 5.4` と DR Table の `M2` ピッチ 5.0（W3.0 + S2.0）は別物**。
> DR 上の最小ピッチは 5.0 だが、**via を打てるピッチは 5.4**。自作フローは全トラックに via を
> 打つ前提なので 5.4 を使う。

### via_1 PCell の使い方

- **カットは全て PDK の `via_1` PCell インスタンス**（手描きしない）。`pdk_tech_python()` が必須
- **`x` は 3.4 のままにする**。TAP の柱も M2 ポートも幅 3.4 で隣との間隔が 2.0 しかない
- **ストラップの幅は `y` で稼ぐ**。`y` を大きくするとカットが配列になる（3.4 → 1 個 / 6.8 → 4 個 / 10.0 → 9 個）
- 同じネットでも **カット間隔 1.5 は効く**。カット 1.4 + 間隔 1.5 → **中心間 2.9 µm 以上**

## 5. 方向規則

**水平は M1、垂直は M2。層が変わるところに必ず via_1。**

M2 は常に垂直のみ。x を変えるときは via_1(M2→M1) → M1 水平 → via_1(M1→M2)（ジョグ）。
チップレベルのリング配線も同じ規則に従う。

> この規則を守ると**すべての交差が M1 × M2 になる**ので、繋ぎたい所にだけ via が現れる。
> これがチップ組み立てで短絡を出さないための最大の仕掛け。
