## 0. 三原則

1. **★ 自作チェッカが 0 を返したことは根拠にならない。**
   最終判断は PDK 公式デッキ（`drc_pdk.py` / `lvs_pdk.py`）と CI の結果で取る
2. **★ LEF は設計の根拠にならない。実ジオメトリ（GDS）を測る。**
   OBS の四隅、フレームの電源ピン、`FOREIGN` — どれも実体と食い違った実績がある
3. **★ 「手元では通るのに CI で落ちる」を最初にツールのバグと決めつけない。**
   **CI と同じコマンドを手元で再現できるようにしてから**でないと切り分けできない

## 1. LVS

### 1-1. ★ トップポート数が合わないと、全ピンが将棋倒しで不一致になる

KLayout はポート数が合わないと**グラフ照合自体を試みない**。下位 27 回路が全部一致していても
「他の全ピンが不一致」という壊れ方をする。

- I2C 版はチップレベル参照から 2 本落としてこれを踏んだ
- 数が合わない時点で中身を見ても無駄。**まずポート数を合わせる**

### 1-2. ★ ラベルだけではサブサーキットのピンが生えない

```
No equivalent pin P10 from reference netlist found in netlist.
This is an indication that a physical connection is not made to the subcircuit.
```

APR_2026 で **出力パッド 5 本ちょうど**（P10/P11/P12/P13/P15）がこれ。
入力パッドはコアから `P<n>` 端子まで配線が来ているので触れているが、**出力パッドはコアが
`OUT<n>` を駆動するだけでボンドパッドの網にトップから何も触れていなかった**。

`klayout_extract.py` は**ラベル層を M2 に繋ぐ**ので自前チェッカでは 44 ピン全部見えていて
気づけなかった（自前と公式で結果が違う典型）。
→ `add_top_pins.py` が**同じ 3 µm 角を M2 (20,0) の実体としても置く**。

### 1-3. ★ ラベルは配線の層に合わせる

`00_Layers.drc` は `labels(48,0)` / `labels(49,0)` **からしかテキストを拾わない**。
48/1・49/1 に置いても無視される。TD4 のメモリ LVS でこれに半日。

層をまたいで拾うのも駄目 — M2 のつもりのラベルが真下の M1 電源レールに付いて
**電源ネットが信号名に化ける**（char の REGBUF で `DD`/`QQ` が vdd レールに付いた）。

### 1-4. ★ 素子数で比較してはいけない

- BUFTH は w=10.2u PMOS / w=6.8u NMOS を **2 フィンガーに折って**描いてある
  → GDS 上のゲート形状 10 個 vs 回路図素子 8 個
- FILL3 のデカップリング 48 個は抽出側で `W=1017.6u` PMOS 1 個（48 × 21.2）
- 回路図側は `m=2` と書くことがある

→ **折り畳み不変量（PMOS 総幅・NMOS 総幅・チャネル長）で比較する。**

### 1-5. ★ SPICE は大文字小文字を区別しない

TD4 メモリ LVS 第 5 回: 内部線 `web` とポート `WEB` が同一ネットに潰れ、
WE バッファ 2 段の入出力が**短絡して見えた**。内部線を `WEBI` に改名して解決。

→ **大小だけで別ネットを作らない。** 照合も大小無視で行う（KLayout の SPICE リーダは
回路名を大文字化する）。

### 1-6. ★ `combine_devices()` は DFFRB で内部エラーを出す

```
Terminal still connected after removing device … circuit=DFFRB, terminal=D
```

→ `lvs_pnr.py` は**両側とも combine しない**方針。
フレームも `mkframespice.py --no-combine` で作った `OSS_FRAME_GIO_nocombine.spice` を使う。
combine 済み（ngspice 用）を混ぜると**素子数が 316 個ずれる**（レイアウト 4225 / ソース 3909）。

このライブラリのセルは全部シングルフィンガで、直列/並列のまとめが要る形が無いので、
**両側とも掛けなければ意味は変わらない。**

### 1-7. 階層のまま渡すと照合できないセルがある

`MUXDFFRB` の xschem export は `x1 DFFRB` / `x2 MUX2` を呼ぶ階層形だが、レイアウトは
1 枚のフラットなリーフセル。**階層のまま渡すと KLayout LVS が照合できない**
（I2C 版 §108.45 で実際に NoMatch / Skipped）。`x1_`/`x2_` プレフィックスで展開する。

### 1-8. flatten では見えない不一致がある

`lvs_pnr.py` は既定で両側 flatten するが、**PDK デッキは階層で比べる**。
1-2 の出力パッド 5 本はこの差で自前側だけ素通りした。

### 1-9. ソース側はレイアウトを見ずに組み立てる

同語反復を避けるため、LVS のソースは**合成ネットリスト + セルの回路図**から作る。
例外は 2 つだけ:
- `FILL2`（デキャップ。回路図が無いのでレイアウト抽出を golden として凍結）
- RING_OSC の `FILL2` の**個数だけ** GDS から数える（回路図の 206 個と一致確認のうえ）

**ソース側にフィラーも入れる**（`FILL2` × 12 / `FILL3` × 68 = 2T のデキャップ）。
入れないとレイアウト側の余剰デバイスとして落ちる。
**`TAP2` はデバイスを持たないので出さない。**

### 1-10. 直列スタックの並び順は回路図と合わせる

TD4 メモリ LVS 第 3 回: NAND4 の NMOS は vss 側から bit3,bit2,bit1,bit0、
NOR2 の PMOS は vdd 側から WEB,RDB。記述が逆で不一致になった。

### 1-11. 構造的に同一なサブ回路はピンの対応が恣意的に決まる

`ADDBUF` は INV 2 段の channel が 4 本で**構造的に完全同一**。KLayout はサブ回路を先に単体比較
するので、レイアウト側のピンが無名（`$2,$3,…`）だと**恣意的に対応を決め**、それがトップに
持ち上がって矛盾する（`Port mismatch 'ADD[0]' vs. 'ADD[3]'` 系 4 件）。
→ ラベルを貼って対応を固定する。**ソースネットリストの修正は不要。**

### 1-12. 説明のつかないポートは固有の `NC_*` で個別に浮かせる

まとめて 1 本にすると、実際には別々に浮いているピン同士を LVS がショートと見なす。

### 1-13. 参照規約と実行コマンド

- デッキの `05_Compare.lvs` は `Sch_file = "simulation/" + source.cell_name + ".spice"`
  → **GDS を置いたディレクトリの `simulation/<トップセル名>.spice`**
- **`-rd circuit=…` / `extracted=…` はレイアウト GDS のあるディレクトリからの相対で解決される**
  → 渡すのは**ファイル名だけ**。パスを付けると `.../src//src/xxx.cir (errno=2)` になる
- **`run.lvs` の `%include` が全部コメントアウトされている**（`lvs.lylvs` の
  `# %include run.lvs` も）。**外さないと何も実行されない**
- モデル名は大文字 `PMOS`/`NMOS`、4 端子 `M<name> D G S B <model> W=..u L=..u`
- **許容差 `W = 1%` / `L = 0%`** — L はぴったり `1.0u` でないと不一致
- バルク端子は PMOS→`vdd`、NMOS→`vss`
- step10 の GDS はトップレベルセルが 15 個ある（未使用セル + `$$$CONTEXT_INFO$$$`）
  → **LVS 時にセル名を明示する**

## 2. DRC

### 2-1. ★ チェッカにトップセルを明示する

2026-08-29: `drc_check.py` の `TOP_CELL` が**渡された GDS に関係なくコアセル名で
ハードコード**されていた。チップレベル GDS への呼び出しは全部、入れ子のコアセルだけを
検査していたので **そのセッションの「0 violations」報告は全部無意味**。
実 KLayout DRC が実違反 50 件を検出。

### 2-2. DRC は差分で見る

パッドリングは元から幅・間隔マーカーを数個持っている（既製ブロック）。
`drc_check.py` の M2 width はフレーム自身で 2000 件以上出る（角のノッチを拾う）。
→ **配線前後の両方で走らせ、増えた分だけ**を座標付きで報告する。

### 2-3. ★ 同名セルの衝突

`ly.read()` でそのまま取り込むと、RING_OSC の中の**旧世代 STDCELL**（prBoundary 64.8、
現行 59.4）が**同名でコア側のセルを上書き**し、**チップの DRC が 8,449 件**に。
自前チェッカは M1/M2/V1 しか見ないので 0 件のまま素通りした。
→ 取り込み時に「中身が同じか」で共有／改名を決める。

同じ理由で `assemble_top.py` が KLayout 既定の `AddToCell` でコアとフレーム両方にある
`via_1` / `via_1$1` を重ね、カットが 0.75 µm ずれて**幅 2.15 の V1 が 15 個**できた。

### 2-4. ★ 自作チェッカに無いルールがある

`docs/10_pdk_facts.md` §3-2。特に:
- **`M1.SW`**: 幅 10 µm 以上の M1 に接する M1 は**間隔 2.0**（自作は一律 1.4）
- **`M1.W3` / `M2.W3`**: M1 / M2 の**最大幅 45 µm**

チップの電源バスバーは**幅ちょうど 10.0 µm** で `M1W` の判定境界に乗っている。
周囲は 2.0 µm 空けておく。

### 2-5. 判定は「未満が違反」

ちょうどは合法。ロゴのドット設計（3.0 µm 角 / 5.0 µm 格子 → 隣接 2.0 µm）はこれに依存。

## 2-b. ★★ KLayout が 2 つある — アプリと pip モジュールは別物

`import klayout.db` が使うのは **pip の `klayout`**。
`/Applications/klayout.app` や `klayout` コマンドを入れても**これは入らない**。

| 何を使うか | 誰が | 入れ方 |
|---|---|---|
| **Python モジュール** `klayout.db` | `place.py` `route.py` `assemble_top.py` `klayout_extract.py` `lvs_pnr.py` ほか 34 本 | `python3 -m pip install klayout` |
| **アプリ**（`klayout -b -r deck.drc`） | `drc_pdk.py` / `lvs_pdk.py`（PDK 公式デッキは Ruby DSL なので**アプリでしか流せない**） | KLayout 本体 |

踏んだ穴（2026-09-15）:

```
$ python3 $APRTOOLS/apr/gen_chip_sim_ready.py
=== 抽出 layout/chip/step3_top_pins.gds (tr_1um_jun1okamura_i2c)
pip install klayout
klayout_extract が失敗した
```

アプリはパスにあるのにこうなる。**メッセージが「pip install klayout」の 1 行しか
出ていなかったので、アプリを入れ直す方向に読めてしまう**のが悪い。
→ `klayout_extract.py` のメッセージを、アプリとの違い・いま動いている
`sys.executable`・入れるコマンドまで出す形に直した。
`selfcheck.py` の `--- 0. 実行環境 ---` でも先に出る。

### ★ シェルの alias は `subprocess` から見えない

`alias klayout='/Applications/klayout.app/Contents/MacOS/klayout -c ~/.myklayoutrc'`
のような alias は **子プロセスに引き継がれない**（`drc_pdk.py` / `lvs_pdk.py` は
`subprocess` で `klayout` を呼ぶ）。

```sh
export KLAYOUT=/Applications/klayout.app/Contents/MacOS/klayout
```

引数付きの alias はそのままでは渡せないので、必要ならラッパを 1 枚作って
`KLAYOUT` にそれを指す。

### ★ 親を正しい python で呼べば子もそれになる

`gen_chip_sim_ready.py` は `sys.executable` で `klayout_extract.py` を起動する。
venv に `klayout` が入っているなら、**親をその venv の python で呼べばよい**
（`PYTHONPATH` は `apr/` を指したまま）。

## 3. ngspice

### 3-1. ★ LVS 用のネットリストは ngspice に使えない

`*_lay.spice` はトップに `.SUBCKT` ポートが無く、ネット名が番号、素子が `M...`
（**PDK の PMOS/NMOS は `.model` ではなくサブサーキットなので `XM` でないと読めない**）。
→ `klayout_extract.py` で**階層とラベルを残したまま**別に抽出する。

### 3-2. ★ 変換が必要な点（回路は触らない）

| # | 変換 | 理由 |
|---|---|---|
| 1 | `M<name> … PMOS` → `X<name>` | PDK の `PMOS`/`NMOS`/`MPE`/`MNE` は `.subckt` |
| 2 | `rx_data[0]` → `rx_data_0` | 角括弧 |
| 3 | `*.PININFO` の `+` 継続行 → `*+` | **コメントは改行で終わるので継続行が回路行として読まれる** |
| 4 | ダイオードの `A=` / `P=` → `AREA=` / `PJ=` | |
| 5 | `NMOSE` → `MNE` | **PDK に `NMOSE` は無い** |
| 6 | `\$107` → `net_107`、`X$1`/`XM$1`/`D$17` → `X_1`/`XM_1`/`D_17` | **`$` は ngspice のコメント文字** |
| 7 | `PAD\|VDD` → `PAD_VDD` | |

**★ 改名は書き出す前に全数の衝突照合にかける。** 別々のネットが同じ名前になると、
後からは本物のショートと区別がつかない。
置換数を全数印字し、書き出し後に KLayout の SPICE リーダで読み直して確認する。

> **「変換して壊れたネットリストは、変換しなかったより悪い。」**

トップ `.SUBCKT` のポートは KLayout がアルファベット順に書くので、
**ボンドパッド順に並べ替える**（並べ替えないと黙ってパッドが入れ替わる）。

### 3-3. ★ `.control` に `run` を書くと解析が 2 回走る

I2C 版の TB がそうなっていた。2 回分の 54 measure が最後の桁まで一致したので
「間違いではなく倍の時間を使っていただけ」と判明。
**`print` を書くと今度は本当に壊れた 2 回目が走る**（I2C 版で踏んだ）。
→ **`.control` は `save` を置くためだけに使う。**

### 3-4. ★ Tmax = 50 ns では通らない

IRSIM・Verilog・ゲートレベルの全てで通るフレームが SPICE だけ落ちる現象を
**数セッション追いかけて**、**Tmax=50ns では 10 ns 未満のセットアップ余裕を解像できず、
適応ステップ制御が誤った側に丸めていた**と判明。
**Tmax を 1 ns にするだけで 10/14 → 14/14。**
区間限定の手段が無いので全区間に効き遅い（37.5 µs で設計機 24 秒 / クラウド約 80 秒）。

### 3-5. `vss` は節点 0 の別名

`Vgnd vss 0 0` は「shorted VSRC」で止まる。**電源は vdd だけ置く。**

### 3-6. 双方向パッドを両側から駆動しない

各パッドに対 VSS の抵抗を入れて動作点の DC 経路と Hi-Z 電位を決める
（DATA 1 MΩ / SDIO 20 kΩ、駆動側は TXGATE/MGATE を DIS に追随させる）。

READ 値は **LSB=1 にする**（LSB が 0 だと「手を離した」と「まだ駆動している」が区別できない）。

### 3-7. ★ 測っているのが部品か測定系かを分ける

20 pF 負荷の掃引が 12 MHz で止まったが、落ちたのは**チップではなく TB のマスタ**
（1 kΩ 直列 × 20 pF = 時定数 20 ns）。`--master-ohm 100` で同じ 20 pF が 15 MHz まで通った。

> **測定系を切り分けられるようにしておかないと、部品に無い上限を報告してしまう。**

同じ理由で **シミュレータが落ちた点は FAIL ではなく ERROR** として区別する。

エッジ時間の扱い: エッジは `TCK/25`（上限 20 ns）で縮めるが、**リセットだけは 100 ns 固定**
（2 ns のランプをリセットパッドの ESD 構造に入れたら "timestep too small" で落ちた掃引点が実在した）。

低速での `tco` はエッジの鈍りによる測定アーティファクトが乗る（1 MHz で 37 ns、
エッジを速くすると 30.7 ns に収束）。

### 3-8. 参照ネットリストは速度を悲観的に見積もる

PDK 既定の `AS/AD = w*sdwidth`、`PS/PD = 2*(sdwidth+w)` は
**行内で隣接セルが共有する拡散を二重に数える**。抽出側は実測なので一度しか数えない。
実測差: `tco_sdio` 38.55 → 37.10 ns（−3.6%）。

### 3-9. 抽出ネットリストの `.extracted` を素の `NetlistSpiceReader` で読むと device 0 に見える

`XM<name> … <MODEL> L= W= AS= PS=` 形式（`NetlistSpiceWriter` + デバイス委譲）なので、
読み戻して比較するならデリゲートが要る（実測: circuit 94 / device 0）。

### 3-10. ESD 素子はモデルが別物

`OSS_PCH_DRV`/`OSS_PCH_ESD` は `MPE`、`OSS_NCH_DRV`/`OSS_NCH_ESD` は `MNE`。
**抽出では PMOS 側が ESD でも `PMOS` と書かれるので、囲っているサブサーキット名で判定する。**

## 4. 配置・配線


### 4-0y. ★ そのまま貼れない見本を手順に書かない

仮名化で実パスを `~/HogeHoge/...` に置き換えたが、**手順のコマンド行にも
そのまま入れてしまった**ので、貼って実行すると

    python3: can't open file '/Users/<自分>/HogeHoge/OpenPDK/...'

で落ちる（実際に踏んだ）。**仮名は「本物に見える偽物」なので一番たちが悪い**
—— 読んだ人は自分のパスに直すのではなく、そのまま貼る。

手順に書くのは**貼っても動くもの**か、**貼ったら明らかに落ちるもの**のどちらか:

```sh
export TR1UM_PDK=<PDK と道具を置いた場所>/TR-1um   # 山括弧。貼れば構文エラーで止まる
export APRTOOLS=<PDK と道具を置いた場所>/TR-1um_APRtools
cd <設計を置いた場所>/<design>
python3 $APRTOOLS/apr/place.py                     # 以降は環境変数だけで書ける
```

**記録**（`** sch_path:` の見出し、合成ログ、凍結した `reference/`）は
仮名のままでよい。そこは「実行するもの」ではないので。

### 4-0z. 「パスと名前」を機械で洗う — `apr/lint.py`

移行で壊れた **7 件が全部「パスと名前」**だった（回路の話は 1 件も無い）ので、
壊れ方そのものを静的に検出する。

```sh
python3 apr/lint.py          # NG があれば 1 で終わる
python3 apr/lint.py -v       # warn も全部出す
#   既定で見るのは apr/ macro/ char/（legacy/ は凍結、templates/ は設計側の見本）
```

`selfcheck.py` が `--- 0. 実行環境 ---` で `NG n / warn n` を出すので、
設計を回す前に目に入る。

| id | 重さ | 何を見るか | 由来した事故 |
|---|---|---|---|
| `escape-apr` | NG | `os.path.dirname(HERE)` で `apr/` の外を見る | `gen_chip_sim_ready` が `../klayout_extract.py` |
| `moved-dir` | NG | `cfg.ROOT` + APRtools へ移したディレクトリ名 | `place_logo` の `cfg.ROOT/lef/opensusi_logo.txt` |
| `baked-path` | NG | `os.path.relpath(x, cfg.ROOT)` が `print` の外 | 提出物に `../apr_root/stdcell/…` |

### 4-0b. ★ 名前の写像漏れは「幾何は正しいのに検査だけ落ちる」形で出る

同日、`route.py` の最後の 1 段だけが落ちた:

```

  FAIL VDD            no PIN marker
```

`step10` の GDS は**正規化 md5 で基準と完全一致**していた。原因は名前だけ:

| どこ | 名前 | 出どころ |
|---|---|---|
| ポート名 | `VDD` / `GND` | **ネットリスト（RTL のモジュール宣言）** |
| PIN マーカのラベル | `vdd` / `vss` | `highlight_top_pins.py` が `rules` で書く |

`verify_port_connectivity.py` がポート名のままマーカを探していた。
境界で写像して解決（`PWR_ALIAS`）。**コアを小文字にしたときの写像漏れは
これで 5 件目**で、5 件とも「パスと名前」。回路の話は 1 件も無い
（`docs/06_verify_migration.md` §5-d）。

### 4-1. ★ 検証の死角 — 「ルータが記録したネット」しか見ないチェッカ

`verify_connectivity_*` は**チャネルルータが記録したネットしか見ず、
ポート→セルピンのスタブが死角**だった。SCLK_SPI ではスカラーポート 9 本が
**まるごと未引き出しのまま最終 GDS に残った**。
→ `verify_port_connectivity.py`（ジオメトリから連結成分を作る）を step8 直後と step10 後に回す。

原因側も典型: `highlight_top_pins.py` に**ポート名が直書き**されており、
その表に載るポートしか探さなかった。バス 16 本だけ偶然一致して通っていた。
→ **ポート名はネットリストの `input`/`output` 宣言から導出する。**

### 4-2. ★ ルータが非決定的

同じ配置 JSON（md5 一致）から step6 が **3 短絡 → 0 短絡と揺れた**。
どこかで集合を反復している（**原因未特定**）。
→ `route.py` / `place.py` の `__main__` で `PYTHONHASHSEED=0` を立てて `os.execv` で起動し直す。
**改名やリファクタの前後比較は必ずこれを立ててから。**

### 4-3. import 時に確定する値が 1 つ前の実行を見る

`PER_ROW_LOCAL_NETS` が読む `cfg.PLACEMENT_JSON` は stage5 が作り直すので、
import 時点では**前回のもの**が残る（配置が同じ md5 なのに短絡が 0→3 になった）。
→ 関数化して使う時点で呼ぶ。行数アサートも `place.py` の生出力から取る。

### 4-4. ★ step5 を忘れると静かに壊れる

`gen_placement_json.py` が `route.py` の外の手作業だった頃、忘れると
**前の設計の配置を今のネットリストに対して配線**していた。
症状は step8 でトップポートが 1 本黙って消えるだけ。
→ stage5 の先頭に取り込み済み。**フローの外に手作業を置かない。**

### 4-5. レイヤ名を M1/M2 に正規化する

TD4 世代の LEF は `METAL1`/`METAL2` と書くがルータは `"M2"` と文字列比較。
直さないと**ピンが 1 本も見つからないまま静かに通る**。
知らない名前は `SystemExit` にすること。

### 4-6. ★ squeeze の 2 つの穴

1. **トップ辺の PIN マーカーを高さ 0 に潰す**（SCLK_SPI で 18 個）。
   「最後に使われたトラックより上のヘッドルームを潰す」規則の巻き添え。
   ラベルもピン形状から外れ、LVS 抽出の規約が壊れる
   → (48,1)/(49,1)/(48,0)/(49,0) の Y 区間を保護区間として identity にする
2. **`compaction_info` は step6 の記録で、step7/8 が足した配線を知らない**。
   記録上「未使用」のトラックに実際は M1 が乗っていて、スライスごと削られ
   **M1 が高さ 0 に潰れて隣と地続き**になる
   → 入力 GDS の M1 を実測して使用トラックに足す

保護区間は `PROTECT_PAD`（既定 1 トラック）で膨らませる。0 にすると保護区間のすぐ脇に
次のトラックが寄って **M1 間隔違反 15 件**。1 で足りるのは M1 パッド 3.4 + 最小間隔 1.4 = 4.8 < 5.4 だから。

### 4-7. チャネル予算は見積もりでは足りない

`place.py` のネット交差数ベースの見積もりでは必ず不足する。
**ルータのジョグ機構は行またぎ 1 本ごとに新しいトラックを確保する**ため。
→ **広めに取って配線 → step10 で圧縮**が正しい運用。

**`CH_HEIGHTS` の上下端は 5.4 の倍数にする。** 131.6/153.2 のままだと ch0 の最上トラックが
row0 のセルの M1 に 1.2 µm まで寄り、**M1 間隔違反が 3 件**出る（step6 で発生し step10 まで残る）。
140.4（26 トラック）/ 162.0（30 トラック）で 0 件。

### 4-8. ★ トップピンの左右振り分けは「行」でなく「ピンの x」で

4 行 + `NO_BOTTOM_PORTS` だと中間行が 3 本になり row0/1 のポートが全部右へ回る。
M1 トランクはピンから行の端まで一直線なので**左端のピンが右端まで 1400 µm 走る**。
実測: `rx_data[5]`（x=229.5）が x=1598.4 まで引かれ `[CHECK] 経路が空いていない` と
自己申告したうえで `scl_gated` と短絡（step8 で発生、step10 まで残存）。

**step8 のトップピンルータは無検査フォールバックを持つ**（「どのトラックも衝突するので
一番マシなものを選んだ」）。→ step8 の形状も `net_shapes` に記録して **step8b で再度 rip-up**。

### 4-9. ポートのネットを配置評価に入れる

`cut_cost` は行またぎしか数えず `hpwl` は `is_port_net` を弾いていた。
実測: リング配線の回り込みが最大 3,529 µm / 合計 56.9 mm、同じ辺に出ているのは 32 本中 5 本。
→ 行割当と行内順序の両方に**パッド近接項**を追加（`_EDGE_ROW` + 重み）。

### 4-10. 同じネットでも via のカット間隔は見る

`exclude_net` は「同じネットなら 1 本の導体」の趣旨だが、**DRC のカット間隔だけは導体が
同じでも効く**。カット 1.4 + 間隔 1.5 → **中心間 2.9 µm 以上**。

### 4-11. spanning のレーンを詰めない

`assign_lanes` は**ジョグ前**の区間でレーンを決めるのに、トランクは**ジョグ後**のピン x で
描かれる。行またぎでピンが右へ動くとトランクが割り当て時の区間を飛び出して隣人を踏む。
使われないトラックは step10 の圧縮が丸ごと削るので、**詰めない方が安い**。

### 4-12. 片側ドッグレッグ

全長を別列へ移す直し方は (a) 全長クリアな列 (b) 両端の via を持ち上げる自由、の両方が要る。
ドッグレッグはどちらも要らず、重なっている所だけ横へ逃がす。
**ドッグレッグが足す via も全部クリアチェックすること**（落として M1 間隔 2 件 + V1 間隔 1 件を出した）。

### 4-13. `component_conflicts` が要る理由

`find_conflicts` は net_shapes の箱同士の**正の重なり**しか見ない。漏れるのは
① 違うネットの箱がぴったり接している（隙間 0。ルータの流儀では合法だが銅では短絡）
② **via のパッド**（via は net_shapes に載らない）
→ step10 と同じ union-find を rip-up ループの中で回す。

### 4-14. 縮退値をそのまま下流に渡さない

マクロを持たない設計では `macro_box()` が `(0,0,0,0)` を返す。
そのまま `extra_protect` に渡すと y=0 に幅ゼロの保護区間ができ、`PROTECT_PAD` で
±1 トラック膨らんで **ch[0] の底が理由もなく圧縮から外れる**。

> オプショナルな機能は Null オブジェクトで表現してよいが、
> **縮退値が下流でどう解釈されるかを 1 箇所ずつ確認する。**

### 4-15. FILL の詰め方

- **右端に固めない。** 区画ごとの目標量を「残りのセル幅 : 残りの容量」の比で決め、
  区画内では `alternate`（偶数区画は右寄せ、奇数は左寄せ、**全行で同じ振り方**）。
  区画の境目に幅の広い空き列が縦一直線に揃う
- 幅 10.8 の隙間からは via パッド 3.4 + 間隔 2.0 が両側に要るので**行またぎ用の x が 1 本しか
  取れない**。140 µm の塊なら 25 本取れる
- **優先コリドーは `FILL3`（16.2 = 3 トラック）を使う。** `FILL2`（10.8 = 2 トラック）だと
  上側トラックの via パッド（半幅 1.7 + 隙間 2.0）が隣のセルへ 1.0 µm はみ出すので、
  隣に M2 があると実質 1 本しか使えない。FILL3 なら真ん中の 1 本が必ず両側とも空く
- **コリドーを増やしても効かない**（実測: ピッチ 108 → 短絡 32 → 40。同じ x に集まりすぎて
  互いに衝突する）。効くのは**配置率そのもの**。
  ただし**短絡が実際に出ている x にだけ 1 本足すのは話が別**（1 本 = 行あたり 16.2 µm で実質タダ）

### 4-16. `sweep_seed.py` の判定ロジック

短絡 0 のとき `PROBLEM(S) FOUND` が出ないのを「配線が落ちた」と誤判定して
**最良シードを捨てていた**（seed 1 と 9 が 0 件なのに seed 8 の 1 件を「最良」と報告）。

## 5. チップ組み立て

### 5-1. ★ 1 ルート = 1 本のポリライン

端子への半径方向ホップをリング本体と**別の `path` 呼び出し**で描くと、
角のビアがどちらの呼び出しの持ち物でもなくなり誰も置かない → **全ネット断線**。
SCLK_SPI はリングと GND 脚で 2 回踏んだ。

### 5-2. ★ 区間は非ラップの `[min,max]` で取る

「全端点を覆う最小の弧」で取ると継ぎ目をまたぐ（ラップする）区間ができ、
詰め込みが**実在しない配線を前提にする** → 同一レーンでの短絡。
向きはその区間に収まる方に強制する。

### 5-3. ★ 幅が変わる継ぎ目はノッチとして拾われる

スタブ幅はコア側ストラップと厳密に一致させる（`TAP_STUB_W = 3.4`）。
ライザーも帯の途中で層を変えると 0.3 µm 侵入した実績がある（帯の上で乗り換える）。

### 5-4. ★ リングの VDD ピン(M1) と VSS ピン(M2) は上辺で重なる

**I2C 版はここで M2 側を VDD のバスだと誤認して一度ショートさせている。**
ライザーは M1 のままでビアを置かない — それが両者を分ける唯一の仕組み。

### 5-5. フレームは四隅のうち 3 隅に自前の PTECT を持つ

SCLK_SPI は GND バスバーを y=−838 に置いて右下 (810,−1120)-(1120,−810) に丸ごと入れた。
→ y=−795 に上げて 15 µm クリアランス。

> **対称性より、そこに実際に何があるかが優先。**

### 5-6. PTECT 削除後の検証を 3 分割する

PTECT を消すと「信号がキープアウトを守ったか」を層で確かめられない。
1. 自分の PTECT マーカーが消えているか（残っていたらルータが走っていない）
2. **フレーム由来の PTECT 3 隅**に金属が入っていないか（消す前後の全レイヤ）
3. 信号ネットが元のボックスに入っていないか（VDD/GND は名指し除外）

### 5-7. 端子の上に via を打たない

フレームの端子 42 本は全部 M1+M2 のスタックでフレーム自身が V1 を打っている。
出ていく向きに合った層（左右辺なら M1、上下なら M2）を選べば**重ねるだけで繋がる**。

### 5-8. 足の重なり

同じ辺で M2 なら 5.4 / M1 なら 3.2 µm 以内に並んだコア側とパッド側の足は、
**パッド側のレーンが外**でないと必ず重なる（実測: 4.1 µm 違いで M2 が 0.7 µm まで寄った）。
`pack()` に下限レーンを渡して解く。

### 5-9. 接続性の probe は層を指定する

コア左辺の M1 ピンが最左の GND TAP 柱（M2、幅 3.4）と重なる位置にあり、
層を省くと左辺 5 本が全部 GND に見える。

### 5-10. ピンの辺は x でなく層で決めることがある

RING_OSC の `ENB`（帯の左下の M2）は x だけで決めると LEFT になり、M1 の足が
RING_OSC の VSS レールのまん中を走って**引いた瞬間に短絡**する。

### 5-11. 同じネット / 同じ端子は 1 本の幹 + 端点ごとの足にまとめる

I2C_2026: `DIS` が P7 から 9 本に枝分かれしてレーンを 9 本食っていた。
→ **32 本 → 23 群、14 レーン → 10 レーン、総長 58,626 → 47,511 µm。**

### 5-12. 1 ネットが何本にも分かれる

ルートはネット名でなく**1 本ずつの `_key`** で持つ。

## 7. セル特性化（`char/`）

### 7-1. ★ ngspice を並列に走らせすぎない

2 コア環境で 2 本同時に走らせると**逐次 2.0 秒の仕事が並列 99 秒**（50 倍）。
ngspice は 1 プロセスで複数スレッドを使おうとし、コア数を超えると桁違いに遅くなる。
`OMP_NUM_THREADS=1` は効かない。`pack/.spiceinit` の `set num_threads=1` も
ビルドによっては効かない。
→ **1 本/秒を大きく下回るなら `-j` を下げる。**

### 7-2. ★ 辺で接する図形は boolean `"or"` で繋がらない

`gdstk.boolean(a,b,"or")` は辺を共有するだけの図形を 1 枚にまとめないことがある。
XOR2 で電源スタブ 2 本の片方が別ネットに割れ、「出力がフルレールに振れない」
**偽の不具合**に見えた。
→ **0.01 µm 膨らませてから結合**（最小間隔は M1 で 1.4 µm あるので誤結合しない）。
ゲート–拡散の接触判定も `bbox` 膨張ではなく `offset` で（bbox だと FILL2/FILL3 の
**L 字のゲート**で片側の拡散を取りこぼす）。

### 7-3. チャネル長を 1.0 µm 決め打ちにしない

`DEL1` の遅延段 4 個は L=2.0 µm、FILL2/FILL3 のデキャップは L=3.2 / 8.6 µm。

### 7-4. ソースとドレインが同じネットに落ちるのは異常ではない

デキャップ。

### 7-5. setup/hold は二分探索でなく掃引で

二分探索は前の結果に依存するので並列化できない。掃引なら全点が独立で、
境界付近を 0.25 ns 刻みにすれば**分解能はむしろ良い**。

### 7-6. クロス結合セルの測り方

測る前に反対側の入力で初期化する。アクティブ端にしかアークが立たない。
反対側は固定容量で見る。**S と R が同じ値になるのが正常 — 片方だけずれたらレイアウトを疑う。**

## 8. 合成・STA

### 8-1. ★ 振る舞いモデルはブラックボックス化する

`blackbox RSLATCH` が無いと `tr1um_cells.v` の振る舞いモデルが展開され、
ABC が入力ゲートごと吸収して **NOR3/NAND3 の生ループ**に化ける
（V10 では組合せループが 4 個できていた）。

セルモデルは `-lib` ではなく**普通の Verilog として**読む
（`-lib` だとブラックボックスのまま残り後段の merge が効かない）。

### 8-2. ★ `dedup_gates.py` を必ず最初に通す

ABC は同じ入力に繋がった同じセルを何個も撒き、それが**配線の混雑と短絡の真の原因**になる。
実測 5 グループ / 35 冗長インスタンス。

### 8-3. STA は merge 後のネットリストに当てる

畳み込み前は NOR2 のクロス結合が生ループとして残り、OpenSTA が勝手にアークを 1 本切る。

### 8-4. クロックの無いコアで `周期 − slack` を使わない

最悪パスが半サイクルパスだと正しく出ない（最初これで「Fmax 0.78 MHz」という誤報を出した）。
→ **周期を 2 点振って `slack(T) = a·T + b` を解く。**

### 8-5. STA にまだ入っていない前提

配線容量ゼロ（**TR-1um の M2 は幅 3.4 µm と太いので実配線が乗ると悪化する**）、
クロックツリー無し、`RSTB` の recovery/removal と min_pulse_width 未特性化
（**`set_false_path -from rstn` で外してよいのは「電源投入時だけのリセット」と
確かめた設計だけ**。SCLK_SPI の `cnt_rstn = rstn & ~cs_n` はフレームごとに
解除されるので前提が崩れる — U8）。`REG8x16` は**読出しアークだけ**が入っている
（書込みの setup/hold は未特性化 — U7）。
Liberty のタイミングがプレースホルダの版は**面積見積もり専用で STA に使えない**。

### 8-6. OpenSTA のビルド（macOS Apple Silicon）

- **Xcode 付属の Tcl/Flex/Bison では通らない。** Homebrew のものを PATH の先に
  （忘れると bison 2.3 が使われ parser 生成で落ちる）
- Homebrew 6.0 以降、**3rd party タップは明示的に信頼しないと読み込まれない**
  （`Refusing to load formula … from untrusted tap`。タップ内の全 formula について出るので
  行数が多いが原因は 1 つ）
- CUDD 自前ビルドの罠 2 つ: ① clone 直後に make すると autotools 再生成で
  `aclocal.m4 Error 127` → `configure.ac aclocal.m4 configure config.h.in Makefile.in`
  の順に `touch` + `sleep` ② 同梱 `config.sub` が 2014 年版で `arm64-apple-darwin` を
  知らない → `--build=aarch64-apple-darwin` を明示

### 8-7. macOS 固有

- bash 3.2 が全角括弧を変数名に含める
- `mktemp` は `XXXXXX` が末尾でないと通らない

## 9. MPW 提出

### 9-1. ★ `pre_check.py` の 2 要求が衝突する

「トップセルはちょうど 1 つ」と「`OSS_FRAME` か `OSS_FRAME_TEG` の存在」。
実体化するのは `OSS_FRAME_GIO` で、素の `OSS_FRAME`/`OSS_FRAME_TEG` はどこからも実体化されず
トップセルになる。標準セルライブラリ丸ごと読みで**トップセルが 17 個**あった。
→ `place_logo.py` が未使用セルを刈り（17 → 1）、`export_mpw.py` が提出用コピーの中だけで
`OSS_FRAME_GIO` → `OSS_FRAME` に改名（**GDS とネットリストの両方に同じ改名**）。
**→ 上流に PR を出す方針**（`docs/11_frame_io.md` §8）。

### 9-2. テンプレート同梱のダミーを消す

`src/tr_1um_username.{gds,cir,sch,extracted}` を本物の隣に残すと**間違ったほうを提出する**。

### 9-3. `pdk.ref` はブランチ名かタグ名のみ

`.github/actions/checkout-pdk` は `git clone --branch` なので**コミット SHA 固定は不可**。
`dev` 追従は動くが再現性がないので、必要な修正を含むタグが切られたら差し替えること。

### 9-4. トップセル名の規約

`tr_1um_` で始まり GitHub ユーザ名を含むこと。

### 9-5. 中間成果物を取り違えない

TD4 は `APR_MACRO_MODE` を付け忘れて `FINAL_GDS` が step10 を指し、
**マクロの vdd/vss が金属で何にも繋がっていないコア**をチップに組み込んだ（2026-09-14）。
→ 最終 GDS の選択は**存在チェック付きで config に持たせる**。

## 10. IRSIM

### 10-1. 並列トランジスタ数の警告

```
There are too many transistors in parallel (> 30)
```

`MAX_PARALLEL`（既定 30）。電源投入直後、ワードラインがまだ X で全 16 行のパスゲートが
「導通かもしれない」状態のときにアレイ全体が 1 つのステージになるため。
アドレスが確定すれば実害なし。

### 10-2. 合否はログだけで完結させる

`.cmd` 言語には条件分岐も算術も無い。読出のたびに
`print CHECK tag=… exp=…` / `assert QV …` / `d AV QV` の 3 行を出して**ログで集計**する
（期待値ファイル不要）。

### 10-3. `settle` を与える

背中合わせインバータの帰還ノードが一瞬の競合で X 判定されないよう `settle 10`。

### 10-4. 配線容量が入っていない

`.sim` に配線形状を持たせていないので、実物はこれより遅い。
最終速度はレイアウト抽出か SPICE で確認すること。
